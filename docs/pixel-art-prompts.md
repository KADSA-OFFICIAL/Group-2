# 픽셀 아트 프롬프트 — 워크 시트 (#380, #418)

두 캐릭터의 워크 시트를 뽑기 위한 프롬프트 모음. 각 프롬프트는 **자기 완결적**이다 —
생성 도구는 이 저장소를 읽지 않으므로 필요한 규약·수치를 프롬프트 안에 전부 적었다.

스펙의 정본은 따로 있다. 값이 바뀌면 **프롬프트가 아니라 아래를 본다.**

| 대상 | 스펙 정본 |
|---|---|
| 아린 | [arin-pixel-art-design.md](arin-pixel-art-design.md) (#344) |
| 익룡 여왕 | [queen-pixel-art-design.md](queen-pixel-art-design.md) (#380) |
| 시트 규약 | [characters/README.md](../assets/sprites/characters/README.md) · [enemies/README.md](../assets/sprites/enemies/README.md) |
| 스킬 이펙트 | [skill-effect-gaps.md](skill-effect-gaps.md) (#387) — **이쪽은 Codex 스크립트다** |

## 어느 도구에 무엇을 시키나

| 산출물 | 도구 | 왜 |
|---|---|---|
| 스킬 이펙트 | **Codex** (Pillow 스크립트) | 원·링·직선뿐이라 코드로 그려진다. 게다가 판정 반경에 맞춰 **연속 배율로 확대·축소**되므로 손으로 찍은 도트가 못 견딘다 → [skill-effect-gaps.md](skill-effect-gaps.md) §4 |
| 캐릭터 워크 시트 | **이미지 생성** (ChatGPT 등) | 얼굴이 있는 치비 스프라이트는 Pillow 도형으로 못 그린다 |

이 문서는 **워크 시트** 쪽이다.
§A 사양 중심(정확한 격자를 받아 주는 도구용) / §B ChatGPT 이미지 생성 절차 /
**§C 남은 대상별 프롬프트**(누가 무엇이 없는지 표 포함).

## 쓰기 전에 — 세 가지

1. **`tint` 결정이 먼저다.** 두 캐릭터 모두 `tint` 가 다른 색과 충돌해 변경이 제안된 상태다
   (아린 문서 §9-1, 여왕 문서 §5-1). 이펙트 색이 전부 `tint` 에서 나오므로 흔들리면 다시 그린다.
   아래 프롬프트는 **제안된 값**(아린 `D9B26A`, 여왕 `8B6BB0`)을 박아 넣었다 — 결정이 달라지면
   프롬프트의 그 줄만 고친다.
2. **재생 코드가 없는 애니메이션은 요구하지 않았다.** Idle·피격·공격·사망·비행은 이 게임에
   재생 경로가 없다. 프롬프트에 넣으면 창고에 쌓인다.
3. **정규화 도구를 쓸지는 어느 경로로 뽑았느냐에 달렸다.**

   | 경로 | `tools/normalize_walk_sheet.gd` |
   |---|---|
   | 격자에 맞춰 찍은 도트 | **쓰지 않는다** — 재배치로 픽셀이 밀린다 |
   | **이미지 생성 산출물** | **반드시 쓴다** — 이 도구가 정확히 그걸 위해 만들어졌다 |

   그 도구의 머리말이 겪은 문제를 적어 두었다: *"셀 폭이 정수로 나뉘지 않는다"*,
   *"프레임마다 캐릭터가 셀 안에서 한쪽으로 흘러간다(측정값 약 29px/프레임).
   그대로 재생하면 제자리걸음이 아니라 옆으로 미끄러진다."*
   ChatGPT 산출물은 **반드시** 이 두 문제를 갖는다(§B-0).

# §A — 사양 중심 프롬프트

정확한 픽셀 격자를 지켜 주는 도구용이다. ChatGPT 이미지 생성에 그대로 넣으면
**격자가 안 맞는다** — 그쪽은 §B 를 쓴다.

## 프롬프트 1 — 아린 워크 시트

```
2D 픽셀 아트 워크 사이클 스프라이트 시트를 만들어 줘. 게임에 바로 넣을 에셋이라
격자 규격을 정확히 지켜야 해.

[출력]
- PNG 1장, 정확히 384 x 512 px, 투명 배경(RGBA)
- 3열 x 4행 = 12칸. 각 칸은 정확히 128 x 128 px
- 업스케일하지 마. 네이티브 128x128 그대로 내보내.
- 안티에일리어싱 금지. 모든 픽셀은 팔레트의 색 중 하나여야 해(중간색 생성 금지).

[격자 의미]
- 행 0 = 정면(아래를 보고 걷기)
- 행 1 = 왼쪽을 보고 걷기
- 행 2 = 뒷모습(위를 보고 걷기)
- 행 3 = 오른쪽을 보고 걷기
- 각 행의 열 0,1,2 = 워크 사이클 3프레임. 0 -> 1 -> 2 -> 0 으로 8fps 반복 재생돼.
- **열 0 은 정지 포즈다.** 캐릭터가 멈추면 이 프레임에서 정지하므로, 서 있는 자세로
  단독 성립해야 해. 양발을 붙이고 무게 중심을 가운데 둬.
- 열 1 = 왼발 앞 + 몸통 1px 아래로. 열 2 = 오른발 앞 + 몸통 1px 아래로.
  열 2 를 열 1 의 좌우 반전으로 만들지 마. 다시 그려.
- 행 3 을 행 1 의 좌우 반전으로 만들지 마. 비대칭 트윈테일이 반대쪽으로 넘어가서
  다른 인물처럼 보여.

[셀 안 배치 — 어긋나면 캐릭터가 공중에 뜬다]
- 캐릭터 키는 108 px. 셀 128 안에서 발바닥이 y = 120 에 닿아야 해(아래 여백 7px).
- 머리 위로 남는 12px(y 0~12)은 트윈테일 들림과 고글 자리야.
- 가로는 셀 중앙 정렬.
- 모든 파츠를 정수 픽셀 그리드에 정렬해. 서브픽셀·회전 금지.

[캐릭터 — 아린]
겸직(원거리 딜러 + 탱커) 여성 캐릭터. 전기 창을 든 도발적인 인상.
108px 키다. 이 3가지만으로 다른 캐릭터와 구분돼야 해(실루엣은 크기가 아니라 모양이 정한다):
  1. 비대칭 트윈테일 — 한쪽이 길게 흘러내림
  2. 어깨의 각진 아우터 — 목 뒤로 솟은 하이칼라
  3. 머리 위 고글 — 실루엣 상단의 가로선
얼굴: 눈·눈썹·입에 더해 코·귀·볼 홍조까지 넣어.
  - 눈: 세로 9px, 가로 12px, 눈 사이 9px. 홍채 안에 3px 하이라이트(광원 반대편)
  - 눈썹: 3~5px. 안쪽 끝을 3px 내려서 호전적인 인상을 만들어
  - 입: 6~9px, 송곳니는 3px 흰 점 하나
  - 코는 1~2px 점, 귀는 실루엣만, 볼 홍조는 옅게
창은 손에 들린 소품이야(던지지 않아). 전체 72px, 파츠 5개:
  창날 21px(이엽, 중앙 3px 슬릿 F7F3EA) / 창날에 1px 각인 2~3획 /
  부유 링 6px(자루와 3px 떨어뜨려) / 자루 45px 3px 굵기 / 자루 감개 3~4곳 가로 1px 띠.
  대각선으로 놓을 땐 45° 고정.
트윈테일 끝단만 6px 진폭으로 흔들되, 몸통보다 1프레임 늦게 따라오게 해.

[팔레트 — 정확히 이 14색만 써. 다른 색을 만들지 마]
머리 하이라이트 #F7F3EA / 머리 메인 #D9B26A / 머리 섀도 #A8823F / 머리 딥섀도 #6E5526
이너 헤어 #6B8FA8 / 이너 헤어 섀도 #4A6879
피부 #DCCDAF / 피부 섀도 #B39A78
의상 다크 #3B342B / 의상 다크 섀도 #2E2A24
의상 앰버 #D9B26A / 의상 앰버 섀도 #A8823F
눈 홍채 #D9B26A / 눈 하이라이트 #F7F3EA
아웃라인 #2E2A24 (1px, 셀렉티브 — 전체를 두르지 말고 실루엣 경계에만)

이 팔레트는 흙 톤 게임에 맞춘 거야. 형광색·채도 높은 원색을 절대 넣지 마.
파트당 3톤 이하. 그라데이션 금지. 디더링은 쓰지 마.
```

## 프롬프트 2 — 아린 이펙트 → **여기서 뽑지 않는다**

아린의 이펙트(낙뢰 3단·감전·넉백 먼지·부채꼴 볼트 결·과부하 3종)는 **이미지 생성이 아니라
Codex 스크립트**로 간다. 이유는 [skill-effect-gaps.md §4](skill-effect-gaps.md) 와 같다 —
착탄 반경 55, 부채꼴 길이 300·각 70°처럼 **판정 수치에 맞춰 확대·축소**되므로
손으로 찍은 도트가 못 견딘다(vfx-guide §1.2: 이펙트 지름 = 판정 지름).

`tools/gen_effects.py` 에 아래를 **추가 항목으로** 넣는다. 별도 스크립트를 만들지 않는다 —
같은 팔레트 상수와 헬퍼를 두 벌 두면 한쪽만 고쳐지는 일이 생긴다.

| 산출물 | 프레임 | 비고 |
|---|---|---|
| `strike_telegraph.png` | 2 | 착탄 예고 링(눌린 타원, 안쪽으로 수축) |
| `strike_bolt.png` | 3 | 강하 볼트. **꺾임은 45°·수직·수평만** |
| `strike_impact.png` | 4 | 착탄 스파크 6갈래 |
| `shock_ring.png` | 3 | 감전. **깜빡이지 않는다** — 0.3초라 껐다 켜면 발작으로 보인다 |
| `dust_puff.png` | 3 | 넉백 먼지. `STONE_GRAY` |
| `bolt_weave.png` | 1 | 부채꼴 내부 결. **가로 타일링 가능**해야 한다 |
| `overload_cast.png` | 3 | 과부하 시전 링 웨이브 |
| `overload_spark.png` | 3 | 부유 스파크 1개 단위(점 → 십자 → 점) |
| `overload_end.png` | 3 | 종료 방전 |

색은 아린의 `tint`(제안값 `D9B26A`)에서 나오므로 **스크립트 상수 하나**로 두고
`tint` 결정이 바뀌면 그 줄만 고쳐 다시 뽑는다 — 이미지 생성이면 전부 다시 그려야 한다.
자세한 프레임별 내용은 [arin-pixel-art-design.md](arin-pixel-art-design.md) §4~§6 이 이미 갖고 있다.

## 프롬프트 3 — 익룡 여왕 워크 시트

```
2D 픽셀 아트 워크 사이클 스프라이트 시트를 만들어 줘. 게임 보스 캐릭터야.
게임에 바로 넣을 에셋이라 격자 규격을 정확히 지켜야 해.

[출력]
- PNG 1장, 정확히 144 x 192 px, 투명 배경(RGBA)
- 3열 x 4행 = 12칸. 각 칸은 정확히 48 x 48 px
- 업스케일하지 마. 네이티브 48x48 그대로.
- 안티에일리어싱 금지. 팔레트 색 외의 중간색 생성 금지.

[격자 의미]
- 행 0 = 정면(아래) / 행 1 = 왼쪽 / 행 2 = 뒷모습(위) / 행 3 = 오른쪽
- 각 행 열 0,1,2 = 워크 3프레임, 8fps 로 0->1->2 반복.
- **열 0 은 정지 포즈다.** 멈추면 이 프레임에서 정지해.
- 행 3 을 행 1 의 좌우 반전으로 만들지 마 — 지팡이가 반대손으로 넘어가.

[셀 안 배치]
- 캐릭터 키 36 px, 발바닥이 y = 44 에 닿게(아래 여백 3px). 가로는 중앙 정렬.
- 머리 위 8px(y 0~7)은 헤드피스 자리.
- 정수 픽셀 그리드 정렬. 서브픽셀·회전 금지.

[캐릭터 — 익룡 여왕]
우아하고 오만한 마법사 여왕. 은발 장발, 보라 드레스, 금 장식, 긴 지팡이.
36px 에서 이 3가지만으로 다른 적(네발 랩터, 덩치 큰 매머드)과 갈려야 해:
  1. 비대칭 스파이크 헤드피스 — 실루엣 상단 오른쪽으로 솟은 뿔 2~3개
  2. 바닥까지 끌리는 드레스 자락 — **실루엣 하단이 넓게 퍼지는 삼각형**
     (위는 좁고 아래가 퍼진다. 이게 다른 적과 갈리는 가장 큰 특징이야)
  3. 오른손의 긴 지팡이 — 실루엣을 세로로 가르는 직선 + 상단에 초승달 고리
     (이 게임에서 세로 직선을 가진 유일한 유닛이야. 반드시 살려)
얼굴은 눈·눈썹·입만:
  - 눈: 세로 3px, 가로 4px. 홍채 #8B6BB0, 1px 하이라이트 #F7F3EA
  - 눈썹: 1px. **바깥쪽 끝을 1px 올려서** 내려다보는 오만한 인상을 만들어
  - 입: 1~2px 옅은 호. 이는 그리지 마

[워크 3프레임 — 발이 아니라 자락으로 걷는다]
드레스가 발목을 덮어 발이 거의 안 보여. 보행은 자락과 머리카락으로 읽혀야 해.
  열 0 = 정지. 무게 중심 중앙, 지팡이 수직, 자락 정지.
  열 1 = 몸통 1px **위로**(뜬다), 자락 왼쪽 2px, 머리카락 끝 1px 뒤로.
  열 2 = 몸통 1px 위로, 자락 오른쪽 2px, 머리카락 끝 1px 앞으로.
- 몸통을 아래로 누르지 말고 **위로** 띄워. 미끄러지듯 걷는 인상이 나야 해.
- 자락·머리카락은 몸통보다 1프레임 늦게 따라와.
- **지팡이는 흔들지 마.** 세로 직선이 식별 요소인데 흔들면 무너져.

[팔레트 — 정확히 이 16색만]
머리 하이라이트 #F7F3EA / 머리 메인 #D8D3CC / 머리 섀도 #9A9691 / 머리 딥섀도 #6E6558
드레스 메인 #8B6BB0 / 드레스 섀도 #5E4578 / 드레스 딥섀도 #3A2C4A
성운 #A78BC8 (드레스 자락 안쪽에 디더링으로만)
금 장식 #D9B26A / 금 장식 섀도 #A8823F
흑 파츠 #3B342B / 흑 파츠 섀도 #2E2A24
피부 #DCCDAF / 피부 섀도 #B39A78
눈 홍채 #8B6BB0
아웃라인 #2E2A24 (1px 셀렉티브)

형광색·원색 금지. 파트당 3톤 이하. 그라데이션 금지.
디더링은 드레스 자락의 성운 표현에만 쓰고 다른 곳엔 쓰지 마.
```

# §B — ChatGPT 이미지 생성 프롬프트

## B-0. 먼저 — 기대치를 맞춘다

**ChatGPT 이미지 생성은 픽셀 정확한 시트를 못 뽑는다.** 이건 프롬프트를 잘 쓰면 되는 문제가
아니라 도구의 성질이다. 실제로 일어나는 일:

| 요구 | 실제 |
|---|---|
| "정확히 144×192" | 1024×1024 같은 자기 기본 해상도로 나온다 |
| "각 칸 48×48" | 칸 폭이 프레임마다 몇 px 씩 다르다 |
| "네이티브 도트, 업스케일 금지" | 도트처럼 **보이는** 고해상도 그림이 나온다 |
| "팔레트 16색만" | 비슷한 색조로 수백 색이 나온다 |
| "행 3을 반전하지 마" | 대체로 지킨다. 다만 확인이 필요하다 |

그래서 §A 처럼 수치를 쌓아 올리면 **대부분 무시되고 프롬프트만 길어진다.**
§B 는 전략이 다르다:

1. **한 번에 한 방향씩** 뽑는다. 12칸을 한 장에 요구하면 격자가 무너진다.
2. **격자·픽셀 수를 요구하지 않는다.** 대신 "가로로 3컷, 간격 넉넉히, 배경 투명"만 말한다.
3. **나온 뒤 `tools/normalize_walk_sheet.gd` 로 격자를 만든다.**
   이 도구는 생성기 산출물을 위해 만들어졌다 — 셀 폭이 정수로 안 나뉘는 것과
   프레임이 셀 안에서 흘러가는 것(측정값 약 29px/프레임)을 둘 다 잡는다.
4. **색은 프롬프트로 굳히지 않고 뽑은 뒤 팔레트로 눌러 넣는다**(B-4).

> 기존 적 시트(돌창병·매머드·벨로시랩터)가 전부 이 경로로 들어왔다.
> `assets/sprites/enemies/README.md` 의 *"원본에서 돌창병 시트를 만든 방법"* 이 그 기록이다.

## B-0b. 화풍 — 치비를 유지하고 **디테일만** 올린다 (#418)

전투 화면은 치비가 맞다. 기존 캐스트(미나·설아·태희)가 이미 치비이고, 남은 둘이 다른 화풍이면
같은 파티에 두 그림체가 선다. **바뀌는 것은 해상도이지 비례가 아니다.**

| 유지 | 올림 |
|---|---|
| 2등신 계열 치비 비례 | 네이티브 해상도 86px → **108px** |
| 납작한 단색 면(그라데이션·글로우 없음) | 얼굴에 코·귀·볼 홍조 |
| 굵고 뚜렷한 외곽선 | 장비 파츠 3개 → 5개 |
| 파트당 3톤 이하 | 의상 계층(안감·벨트·소매), 머리 결 |

**실루엣에는 디테일을 쓰지 않는다.** 식별 요소(트윈테일·고글·창 / 뿔·자락·지팡이)는 지금
모양으로 이미 읽히고, 윤곽을 잘게 만들면 작은 화면에서 오히려 못 알아본다.
늘어난 픽셀은 **윤곽 안쪽**에 쓴다.

> 참고로 기존 캐스트가 밋밋해 보이는 것은 화풍 선택이 아니다 — 네이티브 432px 를 화면 108px 로
> **4배 축소**해서 도트가 1:1 로 안 떨어지고 LINEAR 가 뭉갠다. 소스에 정보가 없어서가 아니라
> 화면에 닿기 전에 버려지는 것이다. 새 규격은 네이티브 = 화면 키라 찍은 도트가 그대로 남는다.

아래 프롬프트에 넣을 한 문단(그대로 복사한다):

```
그림체: 2등신에 가까운 치비 비율. 머리가 크고 몸이 작다.
굵고 뚜렷한 픽셀 아트 — 부드러운 그라데이션·글로우·번짐 없이 단색 면으로.
파트당 3톤 이하(밝은 면 / 기본 / 그림자).

**디테일은 충분히 넣어 줘.** 작고 단순한 아이콘이 아니라, 치비 비율 안에서
얼굴 표정·의상 계층·장비 장식이 또렷하게 보이는 그림이어야 해.
다만 디테일은 **캐릭터 윤곽 안쪽**에만 넣어 — 실루엣(머리 모양, 들고 있는 것)은
단순하고 크게 유지해야 작게 줄여도 누군지 알아볼 수 있어.
```

```
정면(카메라를 보는 방향)으로 서 있는 정지 포즈, 전신, 발끝까지 다 보이게.

굵고 뚜렷한 픽셀 아트 — 부드러운 그라데이션·글로우·번짐 없이 단색 면으로.
파트당 3톤 이하(밝은 면 / 기본 / 그림자). 검은색에 가까운 짙은 갈색 외곽선.

단순하고 크게 유지해야 작게 줄여도 누군지 알아볼 수 있어.

배경은 완전히 투명하게. 그림자나 바닥면을 그리지 마.
```

### 익룡 여왕

```
2D 게임용 치비 픽셀 아트 캐릭터 스프라이트 한 장을 만들어 줘.
정면(카메라를 보는 방향)으로 서 있는 정지 포즈, 전신.

캐릭터: 우아하고 오만한 마법사 여왕. 내려다보는 눈빛.
- 은백색 장발
- 머리 오른쪽으로 솟은 비대칭 뿔 모양 헤드피스(가시 2~3개)
- 바닥까지 끌리는 보라색 드레스. 자락이 넓게 퍼져 실루엣 아래쪽이 삼각형이 된다

그라데이션·글로우 없이 단색 면. 파트당 3톤 이하. 짙은 갈색 외곽선.

또렷하게 보여야 해. 다만 디테일은 **윤곽 안쪽**에만 — 실루엣(뿔, 퍼지는 자락,
세로 지팡이)은 단순하고 크게 유지해.

**지팡이가 화면을 세로로 가르는 직선으로 또렷하게 보여야 해** — 이 캐릭터의 핵심 실루엣이야.
드레스 자락이 지팡이를 가리지 않게.

배경은 완전히 투명하게. 그림자나 바닥면을 그리지 마.
```

## B-2. 방향별 3컷 — 같은 대화에서 이어서

B-1 에서 나온 그림을 **같은 대화에 두고** 아래를 이어 말한다.
새 대화에서 처음부터 시키면 캐릭터가 달라진다 — 그게 이 방식의 가장 큰 위험이다.

```
방금 그 캐릭터로, 걷는 동작 3컷을 가로로 나란히 한 장에 그려 줘.

- 왼쪽부터: ① 두 발을 모은 정지 자세 ② 왼발이 앞으로 나간 자세 ③ 오른발이 앞으로 나간 자세
- 세 컷 모두 **정면**을 보고 있어야 해(방향이 바뀌면 안 돼)
- 세 컷의 **캐릭터 크기와 머리 높이가 정확히 같아야** 해. 확대·축소되면 안 돼
- 컷 사이를 넉넉히 띄우고, 각 컷이 서로 닿거나 겹치지 않게
- 배경은 투명. 컷을 나누는 선이나 테두리를 그리지 마
- 얼굴·머리·옷·창(지팡이)의 모양과 색이 세 컷 모두 완전히 같아야 해

②③ 에서 몸통을 아주 살짝만 위아래로 움직여. 걷는 것처럼 보이면 되고,
크게 움직이면 덜컹거려.
```

그 다음 방향을 바꿔 세 번 더 반복한다. 바꾸는 문장:

| 방향 | 바꿔 넣을 말 |
|---|---|
| 왼쪽 | "세 컷 모두 **왼쪽을 보는 옆모습**으로" |
| 뒷모습 | "세 컷 모두 **뒤를 보는 뒷모습**으로(얼굴이 안 보인다)" |
| 오른쪽 | "세 컷 모두 **오른쪽을 보는 옆모습**으로" |

> **오른쪽을 왼쪽의 좌우 반전으로 때우지 않는다.** 아린은 비대칭 트윈테일이,
> 여왕은 오른손 지팡이가 반대쪽으로 넘어가서 다른 인물로 보인다.
> 각 문서(§3)가 같은 이유로 반전을 금지했다.

### 여왕의 걷기는 다르게 말해야 한다

드레스가 발목을 덮어 **발이 거의 안 보인다.** 위 프롬프트의 ②③ 설명을 이렇게 바꾼다:

```
- ②③ 은 발이 아니라 **드레스 자락과 머리카락**으로 걷는 걸 보여 줘.
  ② 자락이 왼쪽으로 쏠리고 ③ 오른쪽으로 쏠려.
- 몸통은 아주 살짝 **위로** 뜨게 해. 미끄러지듯 걷는 인상이어야 해.
- **지팡이는 흔들지 마.** 세 컷 모두 똑같이 수직으로 서 있어야 해.
```

## B-3. 뽑은 뒤 — 격자 만들기

방향별 3컷 4장이 모이면:

1. 네 장을 **세로로 이어 붙인다**(순서: 정면 → 왼쪽 → 뒷모습 → 오른쪽).
   이 순서는 [`WalkAnimation`](../entities/shared/WalkAnimation.gd) 이 정한 것이라 바꿀 수 없다.
2. 정규화를 돌린다. **이 단계를 건너뛰면 캐릭터가 걸을 때 옆으로 미끄러진다.**

   ```bash
   godot --headless --path . --script res://tools/normalize_walk_sheet.gd -- <입력png> <출력res경로>
   ```

3. 도구가 출력하는 **셀 크기 · 발 기준선 · `walk_sprite_offset` 계산식**을 받아 적는다.
   그 값으로 `.tres` 를 채운다.
4. 도구가 *"내부 절단선 위에 내용 픽셀이 있다"* 고 경고하면 **프레임이 겹쳐 잘렸다는 뜻**이다.
   컷 간격을 더 벌려 다시 뽑는다. (프레임 폭 차이만 알리는 안내는 정상이다 — 포즈 차이다.)

## B-4. 색 눌러 넣기 — 선택

생성 산출물은 수백 색이 섞여 나온다. 기존 시트도 그 상태로 들어왔으니 **필수는 아니다.**
다만 팔레트를 맞추면 다른 캐릭터와 톤이 붙는다.

맞추기로 한다면 `tools/` 에 양자화 스크립트를 하나 두고 **각 픽셀을 팔레트에서 가장 가까운
색으로 스냅**한다. 디더링은 끈다(면이 지저분해진다).
팔레트 값은 [arin-pixel-art-design.md](arin-pixel-art-design.md) §2 ·
[queen-pixel-art-design.md](queen-pixel-art-design.md) §2 표를 그대로 쓴다.

**알파는 건드리지 않는다.** 반투명 가장자리를 색 스냅하면 외곽에 테두리가 생긴다 —
초상 작업에서 실제로 겪은 문제다.

## B-5. 확인 항목

| | 확인 |
|---|---|
| 동일성 | 네 방향의 캐릭터가 **같은 인물**로 보이는가(같은 대화에서 뽑았는가) |
| 반전 | 오른쪽이 왼쪽의 좌우 반전이 아닌가(트윈테일 / 지팡이 손) |
| 크기 | 한 방향 안 3컷의 머리 높이가 같은가 |
| 겹침 | 정규화 도구가 절단선 경고를 내지 않는가 |
| 발 위치 | 전장에 세웠을 때 발이 땅에 닿는가 (아린 108px / 여왕 144px) |
| 필터 | `AnimatedSprite2D.texture_filter = Nearest` 를 걸었는가 |

마지막 두 개는 **화면에 세워 봐야** 안다. 이펙트로 넘어가기 전에 확인한다.

## C-1. 대상별 규격

§1(아린 문서)의 규격을 그대로 쓰되, `F`(충돌 캡슐 절반 높이)가 달라 오프셋이 달라진다.

| 대상 | 캡슐 높이 | `F` | 셀 | 인물 | 배율 | `walk_sprite_offset` | 화면 키 |
|---|---|---|---|---|---|---|---|
| 아린 | 30 | 15 | 128 | 108 | 1 | **(0, -41)** | 108 px |
| 강지 | 30 | 15 | 128 | 108 | 1 | **(0, -41)** | 108 px |
| 서아 | 28 | 14 | 128 | 108 | 1 | **(0, -42)** | 108 px |

```
offset.y = F / scale - (발 기준선 - 셀높이/2)      발 기준선 = 120, 셀 = 128
아린·강지: 15 - 56 = -41      서아: 14 - 56 = -42
```

셋 다 배율 1 이라 도트 1개 = 화면 1px 이고 오프셋이 정수다.

> 서아는 이전 돌창병 대체 시트에서 화면 키가 119px였고, 전용 시트에서는 108px이다.
> 11px 차이라 눈에 띄지 않고, 파티와 같은 키로 서는 편이 오히려 맞다.

### 매머드 우두머리는 지금 하지 않는다

캡슐 높이가 50 이라 `F = 25` 인데, 25 의 약수만 배율이 될 수 있다.

| 배율 | `25/scale` | 화면 키 | |
|---|---|---|---|
| 2 | 12.5 ✗ | — | 오프셋이 소수가 된다 |
| 1 | 25 ✓ | 인물 크기 그대로 | 지금 화면 키 214px 을 맞추려면 **셀 256** 이 필요하다 |
| 5 | 5 ✓ | 인물 43px | 너무 거칠다 |

셀 256 × 12칸을 일관되게 뽑는 것은 생성 도구에 무리다.
캡슐을 50 → **48** 로 2px 줄이면 `F = 24` 라 배율 2 가 되고(`24/2 = 12`,
`offset.y = -44`) 셀 128 로 화면 214px 이 나온다 — 다만 **판정을 바꾸는 일**이라
아트 이슈에서 임의로 정하지 않는다. 지금은 일반 매머드 시트를 계속 빌려 쓴다.

## C-2. 프롬프트 — 강지

§B 의 절차 그대로다: **B-1 로 기준 한 장 → 같은 대화에서 B-2 로 방향별 3컷 ×4.**
아래는 B-1 자리에 넣을 캐릭터 설명이다(공통 그림체 문단은 §B-0b 것을 앞에 붙인다).

```
2D 게임용 치비 픽셀 아트 캐릭터 스프라이트 한 장을 만들어 줘.
정면(카메라를 보는 방향)으로 서 있는 정지 포즈, 전신, 발끝까지 다 보이게.

캐릭터: 밝고 활달한 십대 소녀. 살짝 곤란한 듯 웃는 표정.
- 어깨에 닿는 짧은 갈색 머리. 옆머리를 살짝 땋아 넘겼다
- 머리 오른쪽에 초록 나뭇잎 머리핀, 왼쪽에 작은 실핀 두 개
- 눈동자는 연둣빛 노랑
- 크림색 케이블 니트 가디건을 어깨에 걸쳤다(팔은 소매에 넣었고 앞은 열려 있다)
- 안에는 짙은 올리브색 상의, 아래는 갈색 주름치마에 넓은 가죽 벨트
- 갈색 끈 부츠, 종아리에 크림색 니트 워머
- 어깨에 갈색 가죽 가방을 비스듬히 멨다

색감: 채도가 낮은 흙 톤. 크림, 밝은 갈색, 짙은 올리브, 가죽 갈색.
형광색과 원색을 쓰지 마. 탁한 어스톤이야.

얼굴: 눈썹을 살짝 내려 순한 인상으로. 코·귀·볼 홍조도 넣어.

배경은 완전히 투명하게. 그림자나 바닥면을 그리지 마.
글자, 프레임, 워터마크, 여러 컷을 넣지 마 — 캐릭터 하나만.
```

> **무기를 들리지 마.** 강지의 평타는 근접 즉시타격인데 무기가 저작되어 있지 않다
> (`gangji.tres`). 손에 무엇을 들려 놓으면 전투 화면과 어긋난다.
> 실루엣 식별 요소는 **어깨에 걸친 가디건 + 가방끈 + 나뭇잎 핀** 셋이다.

## C-3. 프롬프트 — 서아 (적)

```
2D 게임용 치비 픽셀 아트 캐릭터 스프라이트 한 장을 만들어 줘.
정면(카메라를 보는 방향)으로 서 있는 정지 포즈, 전신, 발끝까지 다 보이게.

캐릭터: 조용하고 나른한 표정의 소가 섞인 수인 소녀. 적이지만 사납지 않다.
- 허리까지 오는 짙은 갈색 긴 머리, 가운데 가르마
- 머리 양옆에 **위로 굽은 짧은 소뿔** 한 쌍 (크림색)
- 눈동자는 흐린 자갈색, 눈꺼풀을 반쯤 내린 나른한 눈
- 목에 갈색 초커
- 베이지색 오프숄더 니트(어깨가 드러나고 소매가 길다)
- 갈색 무릎 아래 부츠
- 엉덩이 뒤로 **끝에 술이 달린 소꼬리**

색감: 채도가 낮은 흙 톤. 베이지, 짙은 갈색, 크림, 탁한 자갈색.
형광색과 원색을 쓰지 마.

얼굴: 눈꺼풀을 반쯤 내려 나른한 인상으로. 코·귀·볼 홍조도 넣어.

배경은 완전히 투명하게. 그림자나 바닥면을 그리지 마.
글자, 프레임, 워터마크, 여러 컷을 넣지 마 — 캐릭터 하나만.
```

> **무기를 들리지 마.** 서아는 탄을 쏘는 원거리 적인데 탄은 `Projectile` 이 따로 그린다.
> 손에 활이나 지팡이를 그려 넣으면 화면에 없는 것을 약속하게 된다.
> 실루엣 식별 요소는 **소뿔 + 오프숄더 + 꼬리** 셋이다. 이 셋이 돌창병 시트와 갈리는 지점이다.
>
> 뒷모습(행 2)에서 **뿔과 꼬리가 반드시 보여야 한다** — 앞모습만 특징적이면 뒤돌았을 때
> 누군지 모른다. 지금 빌려 쓰는 돌창병 시트가 정확히 그 문제를 갖고 있다.

# 공통 — 산출물이 오면 붙이는 순서

두 캐릭터 모두 같다. **시트를 붙이고 화면에 세워 본 뒤에** 이펙트로 넘어간다 —
키가 어긋난 것을 이펙트를 다 그린 뒤에 발견하면 되돌리는 비용이 크다.

1. PNG 를 각각 `assets/sprites/characters/arin_walk.png` /
   `assets/sprites/enemies/pterosaur_queen_walk.png` 로 넣는다.
   **정규화를 돌릴지는 어느 경로로 뽑았느냐에 달렸다**(위 "쓰기 전에" 3번).
   이미지 생성 산출물이면 §B-3 을 거친 뒤 여기로 온다.
2. `SpriteFrames`(`*_walk_frames.tres`)를 만든다 — 4애니 × 3프레임, 8fps, loop.
   이름은 `walk_down` / `walk_left` / `walk_up` / `walk_right` 고정.
3. `.tres` 에 연결한다.

   | | 아린 | 여왕 |
   |---|---|---|
   | `walk_frames` | `arin_walk_frames.tres` | `pterosaur_queen_walk_frames.tres` |
   | `walk_sprite_scale` | `(3, 3)` | `(4, 4)` |
   | `walk_sprite_offset` | `(0, -15)` | `(0, -15)` |

4. **씬의 `AnimatedSprite2D` 에 `texture_filter = Nearest`** 를 건다.
   전역 설정(`project.godot`)은 건드리지 않는다 — 0.25 로 줄여 쓰는 기존 시트가 거칠어진다.
5. `godot --headless --path . --import` 를 돌리고 `.import` 파일을 함께 커밋한다.
   안 하면 `ResourceLoader.exists()` 가 `false` 라 코드가 파일을 못 찾는다.
6. 전장에 세워 확인한다. 아린은 `stage_1_1`, 여왕은 `stage_test` 4파.
   **발이 땅에 닿는지**와 **화면 키**(아린 108px / 여왕 144px)를 눈으로 본다.
