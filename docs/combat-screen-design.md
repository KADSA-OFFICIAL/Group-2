## 0. 범위

- **[확정]** 현재 작업 대상은 게임의 **메인 전투 화면**이다. 게임 전체가 아니라 전투가 벌어지는 화면의 시스템·레이아웃·승리 조건이 대상.
- **[확정]** 아트/스프라이트는 지금 무시하고 **도형 플레이스홀더**로 대체한다. 시스템·메커니즘에 집중.
- **[확정]** 제작 인원이 한정적이라는 제약이 콘텐츠 총량(유닛 수 등) 결정에 영향을 준다.
- **[확정]** 시점/구도: **탑다운 / 쿼터뷰**.

## 1. 파티 / 로스터

- **[확정]** 전체 로스터 **9명** = 역할군 **3종 × 3명**.
- **[확정]** 역할군 3종: **브루저 / 원거리(원딜) / 버퍼**.
  - 코드상 역할 분류는 `CharacterData.Role` (`MELEE_DEALER` / `RANGED_DEALER` / `BUFFER`)로 이미 존재한다. 이 문서의 브루저/원딜/버퍼는 각각 여기에 매핑된다.
- **[확정]** 플레이어는 9명 중 **3명을 뽑아 파티**를 구성한다. 조합 자유.
- **[확정]** 한 번에 **1명만 직접 조종**, 나머지 2명은 AI가 자동으로 굴린다(실시간 전환).

> 캐릭터 정의/조회는 **`CharacterData` + `CharacterDatabase`(autoload)**를 유일한 출처로 삼는다.
> 로스터를 별도 딕셔너리/하드코딩으로 재정의하지 않는다. (SYSTEM_CONVENTIONS 기초 시스템 규칙)

## 2. 역할 기본기 (역할 공통 정체성) — [확정]

세 역할은 "얼마나 손이 필요한가"라는 축에서 서로 다른 성격을 갖는다. 이 차이가 전환 조작(3장)의 재미를 만든다.

| 역할 | 기본기 | 자원/메커니즘 | 조작 성격 |
|------|--------|---------------|-----------|
| **브루저** | **패링** | 타이밍 맞춰 적 공격을 막고 반격. 잠깐 무적. | **순수 액티브** — 사람이 직접 잡고 눌러야 함 |
| **원딜** | **평타당 공속·이속 증가(스택)** | 평타를 칠수록 스택이 쌓여 공격속도·이동속도 상승 | **반자동** — 평타 기반이라 AI가 굴려도 어느 정도 쌓임 |
| **버퍼** | **표식 → 기절** | 스킬로 적에게 표식 세팅 → 파티 누구든 평타로 채움 → 임계치 도달 시 터지며 기절(CC) | **세팅만 능동, 수확은 파티 전체** |

### 2.1 버퍼 표식 시스템 — [확정]
1. 버퍼를 조종하여 스킬로 적에게 **표식을 세팅**한다(한순간의 능동 행동).
2. 이후 **파티 중 누가 때리든**(원딜/브루저 평타, AI 캐릭터 포함) 평타가 표식을 한 단계씩 채운다.
3. 표식이 **임계치**를 넘으면 터지며 **기절(CC)** 발동.
- 설계 의의: 세 역할이 **하나의 공동 자원(표식)**을 함께 굴린다. 여기서 시너지가 자연 발생한다.

## 3. 스킬 구조 — [확정: 구조 / 미정: 9종 내용]

전투 화면 설계에서 가장 크게 정정된 부분이다.

- **[확정]** 스킬은 "역할 단위 1개"가 아니라 **캐릭터별 고유**다.
  - **역할 기본기(2장의 패링/스택/표식)** = 역할 **공통 정체성**. 같은 역할의 3명이 공유한다.
  - 그 위에 **캐릭터별 고유 액티브 스킬**이 얹힌다(문서 §티어2, 개별 유닛 개성). 총 **9종**.
  - → "원딜의 단일 역할 스킬" 같은 것은 **존재하지 않는다.** (구 문서 §7.1의 "원딜 스킬" 프레이밍은 폐기.)
- **[확정]** **9종 고유 스킬의 구체 설계는 별도 단계로 미룬다.**
  - 전투 화면 **골격은 역할 기본기(패링/스택/표식)로 먼저** 굴린다.
  - 원딜은 기본기(스택)만으로도 동작하므로, 골격 단계에서 별도 액티브 스킬이 없어도 전투가 성립한다.

> **[미정]** 9명 각각의 고유 스킬/무기 내용.

## 4. 조작 / 전환 리듬 — [확정]

- **[확정]** **3명을 실시간 전환하며 조작.** 1명 직접 조종 + 2명 AI.
- **[확정]** **AI 수준 = "중간"**: 안 잡은 2명은 **기본기(평타·이동·생존)는 스스로** 하되, **스킬은 쓰지 않는다.** 스킬은 반드시 **사람이 직접 잡아야 발동.**
  - 브루저 패링 = 스킬성 액티브 → AI는 패링 안 함(그냥 맞음). 잡아야만 발동.
  - 원딜 스택 = 평타 기반 → AI도 평타는 치므로 놔둬도 어느 정도 쌓인다.
  - 버퍼 표식 세팅 = 스킬 → AI는 못 찍음. 사람이 잡아 세팅해야 함. (세팅 후 표식 채우기는 AI 평타로도 가능.)

### 4.1 자원 유지 규칙 — [확정]
- **스택처럼 쌓이는 수치(원딜 공속 스택 등)는 전환해서 놓으면 "서서히 감소"한다.** (즉시 리셋도, 완전 유지도 아님.)
- 이 규칙이 전투의 심장 리듬을 만든다:

```
① 원딜 잡고 평타로 스택 쌓기
        ↓
② 스택 최고조에서 다른 캐릭터로 전환
        ↓
③ 브루저(패링)·버퍼(표식) 등 액티브 스킬 꽂기
   (이 동안 원딜 스택은 서서히 감소)
        ↓
④ 스택이 빠지기 전에 다시 원딜로 복귀 → 스택 리필
        ↺ 반복
```

- 즉시 리셋이면 원딜을 못 놓아 전환이 죽고, 완전 유지면 긴장이 없다. "서서히 감소"가 **"언제 원딜로 돌아갈까"**를 매 순간 계산하게 만든다.

## 5. 전투 목표 / 승리 조건 — [확정]

- **[확정]** **최종 목표는 상대 진영/마을 "점령"이다.** (구 문서의 "웨이브 전멸"은 폐기.)
- **[확정]** 승리 조건은 **하나로 고정하지 않고 스테이지별로 달라진다(데이터 기반).**

### 5.1 목표 프리미티브 — [확정]
승리 조건은 아래 두 프리미티브의 조합으로 구성한다.

| 프리미티브 | 의미 |
|---|---|
| **소탕** | 방어 병력을 전멸시킨다. |
| **점령** | 거점 존(zone)에 들어가 일정 시간 확보한다. |

### 5.2 스테이지 타입 3종 — [확정]

| 타입 | 승리 조건 |
|---|---|
| **전투** | 소탕만 (방어 병력 전멸 시 승리) |
| **점령** | 점령만 (거점 존 확보 시 승리) |
| **점령+전투** | 소탕 + 점령 둘 다 |

- **[미정]** "점령+전투"에서 두 프리미티브를 **순차/동시/보완** 중 어떤 방식으로 엮을지의 세부.
- **[미정]** 각 타입의 세부 파라미터(존 확보 시간, 존 위치, 리스폰 규칙 등).
- **[확정 연결]** 이 승리 조건은 상위 루트 선택(잠입 vs 전투, §7)과 맞물린다. 잠입 루트는 비전투로 목표를 달성한다.

## 6. 메인 전투 화면 HUD — [확정]

화면에 반드시 있어야 하는 요소:
- 파티 3명 표시 (조종 중 1명 강조 + 대기 2명 AI 작동 표시)
- 전환 UI (1/2/3 키 또는 카드 클릭)
- 원딜 스택 게이지 (차고 서서히 빠지는 것이 눈에 보여야 함)
- 적 위의 표식 카운터 (현재 표식 수 / 임계치)
- 패링 인디케이터 (브루저 조종 중 타이밍 표시)
- 각자 체력 / 스킬 쿨다운
- (스테이지 타입에 따라) 점령 게이지 / 거점 존 표시

> HUD 코드도 값의 소유·계산은 기초 시스템에 두고, 그 값을 **읽어서 표시**만 한다.
> 스텟은 `PlayerStats`, 캐릭터는 `CharacterDatabase`에서 가져온다. UI 편의를 위한 어댑터는 둘 수 있으나 값의 출처는 기초 시스템이다.

## 7. 스테이지 진행 / 루트 (전투 화면 밖, 방향만 확정)

- **[확정]** 스테이지 진입 **전에** 클리어 방식을 선택한다: **비전투(잠입) 루트** / **전투 루트**. (들켜서 전환되는 게 아니라 진입 전 선택.)
- **[확정]** 잠입에서도 역할군이 차별화된다: 버퍼=기만·변장(택배 사칭), 원딜=정찰·원거리 무력화, 브루저=은밀 제압.
- **[미정]** 잠입 루트의 실제 게임플레이(현재 전투 화면 작업 범위 밖).
- **[미정]** 방어기지 공략(파괴/비파괴), 점령 방식(협상/전투)의 구체 규칙.

---

## 8. 시너지 (구조만 확정)

- **[확정]** 2층 구조. (개별 유닛 조합마다 짜면 관리 불가 → 계층 분리.)
  - **티어1 — 역할 구성 시너지**: 시너지를 개별 유닛이 아니라 "역할 구성"에 붙인다. 순혈=강하지만 리스크 / 무지개(1/1/1)=약하지만 안정 / 2+1=중간.
  - **티어2 — 개별 유닛 개성**: 같은 역할 3명이 서로 다른 스킬/무기(§3의 캐릭터별 고유 스킬).
- **[확정된 관찰]** 표식 시스템 덕에 **원딜+버퍼**는 "세팅 → 고속 수확 → 기절 연발" 시너지가 자연 발생.
- **[미정]** 티어1 시너지 10종의 구체 효과. 티어2 유닛별 구체 내용.

---

## 9. 미정 사항 요약 (다음에 정할 것)

1. **[미정]** 9명 각각의 고유 스킬/무기 (티어2 내용).
2. **[미정]** "점령+전투" 타입의 프리미티브 결합 방식, 각 스테이지 타입 세부 파라미터.
3. **[미정]** 티어1 시너지 10종 구체 효과.
4. **[미정]** 방어기지 공략(파괴/비파괴), 점령 방식(협상/전투) 구체 규칙.
5. **[미정]** 잠입 루트 실제 게임플레이.

### 조정 가능한 임시 수치 — [임시값]
감을 잡은 뒤 밸런싱 대상.
- 표식 임계치: 5
- 패링 윈도우: 0.45초
- 원딜 스택 감소 속도: 조종 중 느리게 / 미조종 시 더 빠르게
- 각종 스킬 쿨다운, 평타 데미지, 이동속도, 적 체력, 점령 확보 시간 등 전부 임시.

## 10. 기초 시스템 준수 (구현 시 필독)

전투 화면 구현은 아래 기초 시스템 **위에 얹어** 만든다(병렬 재구현 금지). 상세는 [SYSTEM_CONVENTIONS.md](../SYSTEM_CONVENTIONS.md).

| 도메인 | 기초 시스템 | 출처 |
|---|---|---|
| 재화 | `CurrencySystem` | `DEFAULT_CURRENCIES` |
| 스텟 | `PlayerStats` | 기초/파생 스텟 |
| 캐릭터 | `CharacterData` + `CharacterDatabase` | 캐릭터 정의/조회 |
| 장비 | `EquipmentData` + `EquipmentDatabase` + `EquipmentSystem` | 장비 정의/조회, 제작·착탈 |
