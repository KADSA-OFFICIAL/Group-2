# 전투 화면 설계 (Combat Screen Design)

> **이 문서의 위치**
> 이 문서는 저장소 안의 **전투 화면 설계 정본(source of truth)**이다.
> 외부(다운로드 폴더 등)에 존재하는 브레인스토밍 md나 `*_prototype.html`은 참고용일 뿐, 확정 설계의 기준은 이 문서다.
>
> 각 항목의 상태 표기:
> - **[확정]**: 합의된 사항. 임의로 바꾸지 말 것.
> - **[미정]**: 아직 결정하지 않은 공백. 다음에 정할 것.
> - **[임시값]**: 프로토타입/구현 편의를 위한 임의 값. 밸런싱 대상.
>
> 관련 규칙: [SYSTEM_CONVENTIONS.md](../SYSTEM_CONVENTIONS.md), [CLAUDE.md](../CLAUDE.md)의 "기초 시스템" 절.

## 0. 범위

- **[확정]** 현재 작업 대상은 게임의 **메인 전투 화면**이다. 게임 전체가 아니라 전투가 벌어지는 화면의 시스템·레이아웃·승리 조건이 대상.
- **[확정]** 아트/스프라이트는 지금 무시하고 **도형 플레이스홀더**로 대체한다. 시스템·메커니즘에 집중.
- **[확정]** 제작 인원이 한정적이라는 제약이 콘텐츠 총량(유닛 수 등) 결정에 영향을 준다.
- **[확정]** 시점/구도: **탑다운 / 쿼터뷰**.

## 1. 파티 / 로스터

- **[확정]** 전체 로스터 **6명**.
- **[확정]** 역할군 3종: **탱커 / 원거리딜러 / 버퍼**.
  - 코드상 역할 분류는 `CharacterData.Role` (`TANK` / `RANGED_DEALER` / `BUFFER`)에 매핑된다.
- **[확정]** 플레이어는 6명 중 **3명을 뽑아 파티**를 구성한다. 조합 자유.
- **[확정]** 한 번에 **1명만 직접 조종**, 나머지 2명은 AI가 자동으로 굴린다(실시간 전환).

### 1.1 로스터 구성 — [확정]

6명은 **순혈 3명 + 겸직 3명**으로 나뉜다.

| 구분 | 캐릭터 | 가진 역할 |
|---|---|---|
| 순혈 | 탱커 | 탱커 |
| 순혈 | 원거리딜러 | 원거리딜러 |
| 순혈 | 버퍼 | 버퍼 |
| 겸직 | 탱커/버퍼 | 탱커 + 버퍼 |
| 겸직 | 원거리/탱커 | 원거리딜러 + 탱커 |
| 겸직 | 버퍼/원거리 | 버퍼 + 원거리딜러 |

- **겸직 캐릭터는 두 역할 카운트에 동시에 기여한다.** 이것이 시너지(8장) 계산의 핵심이다.
- **[미정]** 6명 각각의 이름·개성·고유 스킬.

> 캐릭터 정의/조회는 **`CharacterData` + `CharacterDatabase`(autoload)**를 유일한 출처로 삼는다.
> 로스터를 별도 딕셔너리/하드코딩으로 재정의하지 않는다. (SYSTEM_CONVENTIONS 기초 시스템 규칙)

## 2. 역할 기본기 (역할 공통 정체성) — [확정]

세 역할은 "얼마나 손이 필요한가"라는 축에서 서로 다른 성격을 갖는다. 이 차이가 전환 조작(3장)의 재미를 만든다.

| 역할 | 기본기 | 자원/메커니즘 | 조작 성격 |
|------|--------|---------------|-----------|
| **탱커** | **표식 → 기절** | 탱커의 **스킬과 평타**가 적에게 표식을 생성 → 표식이 걸린 적을 **파티 전체의 평타**가 일정 횟수 때리면 기절(CC) | **반자동 생성 + 파티 전체 수확** |
| **원거리딜러** | **평타당 공속·이속 증가(스택)** | 평타를 칠수록 스택이 쌓여 공격속도·이동속도 상승 | **반자동** — 평타 기반이라 AI가 굴려도 어느 정도 쌓임 |
| **버퍼** | **처형** | 디버프가 걸린 적을 **버퍼가 직접** 공격할 때, 적 체력이 일정 이하면 처형 | **조건부 능동** — 버퍼를 직접 잡아야 처형이 발동 |

> **[폐기]** 이전 설계의 "브루저 = 패링(타이밍 방어 + 반격)"은 폐기되었다.
> 역할이 브루저 → **탱커**로 바뀌면서 성격 자체가 달라졌고, 표식이 버퍼에서 **탱커로 이동**했다.

### 2.1 탱커 표식 시스템 — [확정]
1. **탱커의 스킬과 평타**가 적에게 **표식을 생성**한다.
2. 이후 **파티 중 누가 때리든**(AI가 굴리는 캐릭터 포함) 평타가 표식을 한 단계씩 채운다.
3. 일정 횟수에 도달하면 터지며 **기절(CC)** 발동.
- 이전 버퍼 표식과의 차이: 스킬로만 세팅하던 것이 **평타로도 생성**되도록 바뀌었다. 그래서 탱커를 직접 잡지 않아도 AI 평타로 표식이 어느 정도 생성된다.
- 설계 의의: 세 역할이 **하나의 공동 자원(표식)**을 함께 굴린다. 여기서 시너지가 자연 발생한다.

### 2.2 버퍼 처형 시스템 — [확정]
1. 적에게 **디버프**가 걸려 있어야 한다.
2. **버퍼가 직접** 그 적을 공격한다(파티원 공격으로는 발동하지 않는다).
3. 적 체력이 **임계치 이하**면 **처형**된다.
- 디버프는 상태 효과 시스템(`StatusEffectData`의 `is_debuff`)이 출처다. 처형 조건을 위해 디버프를 따로 정의하지 않는다.
- **[미정]** 처형 체력 임계치 수치, 그리고 "어떤 디버프든 되는지 / 특정 디버프여야 하는지".

## 3. 스킬 구조 — [확정: 구조 / 미정: 6종 내용]

- **[확정]** 스킬은 "역할 단위 1개"가 아니라 **캐릭터별 고유**다.
  - **역할 기본기(2장의 표식/스택/처형)** = 역할 **공통 정체성**. 같은 역할을 가진 캐릭터가 공유한다.
  - 그 위에 **캐릭터별 고유 액티브 스킬**이 얹힌다(8장 티어2, 개별 유닛 개성). 로스터 6명이므로 총 **6종**.
  - → "원거리딜러의 단일 역할 스킬" 같은 것은 **존재하지 않는다.**
- **[확정]** **6종 고유 스킬의 구체 설계는 별도 단계로 미룬다.**
  - 전투 화면 **골격은 역할 기본기(표식/스택/처형)로 먼저** 굴린다.
- **[미정]** 겸직 캐릭터가 **두 역할의 기본기를 모두 갖는지**, 아니면 한쪽만 갖는지. (시너지 카운트에는 두 역할 모두 기여하는 것이 확정이나, 기본기 보유 여부는 별개 문제다.)

> **[미정]** 6명 각각의 고유 스킬/무기 내용.

## 4. 조작 / 전환 리듬 — [확정]

- **[확정]** **3명을 실시간 전환하며 조작.** 1명 직접 조종 + 2명 AI.
- **[확정]** **AI 수준 = "중간"**: 안 잡은 2명은 **기본기(평타·이동·생존)는 스스로** 하되, **스킬은 쓰지 않는다.** 스킬은 반드시 **사람이 직접 잡아야 발동.**
  - 탱커 표식 = 스킬 + **평타** 기반 → AI도 평타는 치므로 놔둬도 표식이 어느 정도 생성된다. 스킬 표식은 잡아야 발동.
  - 원거리딜러 스택 = 평타 기반 → AI도 평타는 치므로 놔둬도 어느 정도 쌓인다.
  - 버퍼 처형 = **버퍼가 직접 공격**해야 하는 조건 → 사람이 버퍼를 잡아야 처형이 나온다.
  - 표식 채우기는 **파티 전체 평타**로 이뤄지므로 AI가 굴리는 캐릭터도 기여한다.

### 4.1 자원 유지 규칙 — [확정]
- **스택처럼 쌓이는 수치(원거리딜러 공속 스택 등)는 전환해서 놓으면 "서서히 감소"한다.** (즉시 리셋도, 완전 유지도 아님.)
- 이 규칙이 전투의 심장 리듬을 만든다:

```
① 원거리딜러 잡고 평타로 스택 쌓기
        ↓
② 스택 최고조에서 다른 캐릭터로 전환
        ↓
③ 탱커(표식 스킬)·버퍼(처형) 등 액티브 꽂기
   (이 동안 원거리딜러 스택은 서서히 감소)
        ↓
④ 스택이 빠지기 전에 다시 원거리딜러로 복귀 → 스택 리필
        ↺ 반복
```

- 즉시 리셋이면 원거리딜러를 못 놓아 전환이 죽고, 완전 유지면 긴장이 없다. "서서히 감소"가 **"언제 원거리딜러로 돌아갈까"**를 매 순간 계산하게 만든다.

## 5. 전투 목표 / 승리 조건 — [확정]

- **[확정]** **최종 목표는 상대 진영/마을 "점령"이다.** (구 문서의 "웨이브 전멸"은 폐기.)
- **[확정]** 승리 조건은 **하나로 고정하지 않고 스테이지별로 달라진다(데이터 기반).**

### 5.1 목표 프리미티브 — [확정]
승리 조건은 아래 두 프리미티브의 조합으로 구성한다.

| 프리미티브 | 의미 |
|---|---|
| **소탕** | 방어 병력을 전멸시킨다. |
| **점령** | 거점 존(zone)에 들어가 일정 시간 확보한다. |

### 5.2 스테이지 타입 3종 — [확정]

| 타입 | 승리 조건 |
|---|---|
| **전투** | 소탕만 (방어 병력 전멸 시 승리) |
| **점령** | 점령만 (거점 존 확보 시 승리) |
| **점령+전투** | 소탕 + 점령 둘 다 |

- **[미정]** "점령+전투"에서 두 프리미티브를 **순차/동시/보완** 중 어떤 방식으로 엮을지의 세부.
- **[미정]** 각 타입의 세부 파라미터(존 확보 시간, 존 위치, 리스폰 규칙 등).
- **[확정 연결]** 이 승리 조건은 상위 루트 선택(잠입 vs 전투, §7)과 맞물린다. 잠입 루트는 비전투로 목표를 달성한다.

## 6. 메인 전투 화면 HUD — [확정]

화면에 반드시 있어야 하는 요소:
- 파티 3명 표시 (조종 중 1명 강조 + 대기 2명 AI 작동 표시)
- 전환 UI (1/2/3 키 또는 카드 클릭)
- 원거리딜러 스택 게이지 (차고 서서히 빠지는 것이 눈에 보여야 함)
- 적 위의 표식 카운터 (현재 표식 수 / 임계치)
- 처형 가능 표시 (버퍼 조종 중, 디버프 + 체력 임계치 조건을 만족한 적)
- 각자 체력 / 스킬 쿨다운
- **역할군 시너지 표시** (역할별 현재 카운트와 활성 단계 1/3)
- (스테이지 타입에 따라) 점령 게이지 / 거점 존 표시

> HUD 코드도 값의 소유·계산은 기초 시스템에 두고, 그 값을 **읽어서 표시**만 한다.
> 스텟은 `PlayerStats`, 캐릭터는 `CharacterDatabase`에서 가져온다. UI 편의를 위한 어댑터는 둘 수 있으나 값의 출처는 기초 시스템이다.

## 7. 스테이지 진행 / 루트 (전투 화면 밖, 방향만 확정)

- **[확정]** 스테이지 진입 **전에** 클리어 방식을 선택한다: **비전투(잠입) 루트** / **전투 루트**. (들켜서 전환되는 게 아니라 진입 전 선택.)
- **[확정]** 잠입에서도 역할군이 차별화된다: 버퍼=기만·변장(택배 사칭), 원거리딜러=정찰·원거리 무력화, 탱커=은밀 제압.
- **[미정]** 잠입 루트의 실제 게임플레이(현재 전투 화면 작업 범위 밖).
- **[미정]** 방어기지 공략(파괴/비파괴), 점령 방식(협상/전투)의 구체 규칙.

## 8. 시너지 (구조 확정 / 효과 미정)

- **[확정]** 2층 구조. (개별 유닛 조합마다 짜면 관리 불가 → 계층 분리.)
  - **티어1 — 역할군 시너지**: 시너지를 개별 유닛이 아니라 **역할군 카운트**에 붙인다.
  - **티어2 — 개별 유닛 개성**: 캐릭터마다 서로 다른 고유 스킬(§3).

### 8.1 티어1 — 역할군 카운트 시너지 — [확정: 구조]

- **[확정]** 파티(3명)에서 각 역할군이 몇 카운트인지를 센다.
- **[확정]** **겸직 캐릭터는 자신이 가진 두 역할 카운트에 각각 +1** 기여한다.
- **[확정]** 활성화 임계치는 **1과 3**:

| 카운트 | 활성화 |
|---|---|
| 0 | 비활성 |
| 1~2 | **1단계** 효과 |
| 3 | **1단계 + 3단계** (3단계는 1단계 위에 **추가 누적**) |

- 즉 3카운트는 1단계를 대체하는 것이 아니라 **1단계를 유지한 채 별도 효과가 더해진다.**
- **[미정]** 역할군별 1단계/3단계의 **구체 효과**(총 6개: 탱커·원거리딜러·버퍼 × 1단계·3단계).

### 8.2 조합 특성 — [구조에서 도출됨]

로스터 6명(순혈 3 + 겸직 3), 파티 3명이라는 구조에서 아래가 따라 나온다. 설계 검증용 기록이며, 별도로 정한 규칙이 아니다.

- 전체 파티 조합은 **20가지**(6C3).
- **3카운트에 도달하는 파티는 정확히 3가지**뿐이다. 각 역할마다 `해당 역할 순혈 + 그 역할을 가진 겸직 2명` 조합 하나씩:
  - 탱커 3카운트: 순혈 탱커 + 탱커/버퍼 + 원거리/탱커
  - 원거리 3카운트: 순혈 원거리 + 원거리/탱커 + 버퍼/원거리
  - 버퍼 3카운트: 순혈 버퍼 + 탱커/버퍼 + 버퍼/원거리
- **한 파티가 두 역할을 동시에 3카운트로 만들 수는 없다.** 겸직 3명을 모두 넣으면 2/2/2가 되어 오히려 아무 역할도 3에 도달하지 못한다.
- **특정 역할이 0카운트가 되는 파티도 존재한다** (예: 순혈 탱커 + 순혈 원거리 + 원거리/탱커 → 버퍼 0).
- 설계 의의: 3단계 시너지가 **희귀하고 의도적인 선택**이 되며, "몰빵이냐 분산이냐"의 고민이 카운트 구조 자체에서 자연 발생한다.

### 8.3 자연 발생 시너지 — [확정된 관찰]

- 표식은 **파티 전체 평타**로 채워지므로, 공속이 빠른 **원거리딜러**가 있으면 탱커 표식이 빠르게 터진다 → **탱커 + 원거리딜러**는 설계하지 않아도 시너지가 난다.
- 버퍼 처형은 **디버프**를 조건으로 하므로, 디버프를 거는 수단이 많을수록 처형 기회가 늘어난다.

> **[미정]** 티어2 유닛별 구체 내용(6명 각각의 고유 스킬).

## 9. 미정 사항 요약 (다음에 정할 것)

1. **[미정]** 6명 각각의 이름·개성·고유 스킬/무기 (티어2 내용).
2. **[미정]** **티어1 시너지 구체 효과 6개** — 탱커/원거리딜러/버퍼 × 1단계/3단계.
3. **[미정]** 겸직 캐릭터가 두 역할의 **기본기를 모두 갖는지** 여부 (시너지 카운트 기여는 확정).
4. **[미정]** 버퍼 처형의 체력 임계치, 그리고 조건이 되는 디버프의 범위(아무 디버프 / 특정 디버프).
5. **[미정]** "점령+전투" 타입의 프리미티브 결합 방식, 각 스테이지 타입 세부 파라미터.
6. **[미정]** 방어기지 공략(파괴/비파괴), 점령 방식(협상/전투) 구체 규칙.
7. **[미정]** 잠입 루트 실제 게임플레이.

### 조정 가능한 임시 수치 — [임시값]
감을 잡은 뒤 밸런싱 대상. 수치의 코드상 출처는 `autoload/CombatConfig.gd`다.
- 표식 임계치: 5
- 표식 충전량(평타 1회당): 1
- 원거리딜러 스택 감소 속도: 조종 중 느리게 / 미조종 시 더 빠르게
- 버퍼 처형 체력 임계치: 미정
- 각종 스킬 쿨다운, 평타 데미지, 이동속도, 적 체력, 점령 확보 시간 등 전부 임시.

> **[폐기]** 패링 윈도우(0.45초)는 브루저 패링이 폐기되면서 함께 폐기되었다.
