# 아린 (Arin) — 2D 픽셀 아트 디자인 문서

전기 창 캐릭터. 도트 그래픽.

> **이 문서의 위치**
> 아린 **아트 스펙 전용**이다. 구현 코드는 담지 않는다.
> 이펙트 규약의 정본은 [vfx-guide.md](vfx-guide.md), 워크 시트 규약의 정본은
> [assets/sprites/characters/README.md](../assets/sprites/characters/README.md),
> 전투 규칙·수치의 정본은 [combat-screen-design.md](combat-screen-design.md)다.
> 이 문서는 그 위에 "아린을 어떻게 그릴 것인가"만 얹는다.
>
> **여기에 적힌 전투 수치는 전부 인용이다.** 값의 소유자는 `data/` 의 `.tres` 다.
> 값이 바뀌면 이 문서가 아니라 데이터를 본다 — 그래서 모든 수치에 **출처 파일과 필드명**을 붙였다.
> 순수 연출값(프레임 수, 페이드, 링 두께)만 이 문서가 소유한다(vfx-guide §1.3).

## 0. 지금 있는 것 / 없는 것

**있다 — 그릴 대상의 행동이 이미 확정되어 있다.**

아린은 전투가 저작되고(#336) 이름을 받은(#338) 상태다.
[`data/characters/arin.tres`](../data/characters/arin.tres) 가 스스로 적고 있다:
*"워크 시트도 초상도 없어 전투에서 도형 플레이스홀더(shape_ranged)로 보이고 메타 화면에는
초상이 뜨지 않는다."* 즉 **남은 것은 아트뿐**이다.

| 항목 | 값 | 출처 |
|---|---|---|
| 역할 | 겸직 — 원거리딜러 + 탱커 | `arin.tres` `role = 1`, `secondary_role = 1` |
| 체력 / 근력 / 방어 | 1100 / 110 / 110 `[임시값]` | 같은 파일 `stats` |
| 평타 | **낙뢰** (탄 없음, 대상 자리에 즉시) | 같은 파일 `basic_attack_*` |
| Q | 부채꼴 밀어내기 | [`arin_sweep.tres`](../data/skills/arin_sweep.tres) |
| E | 과부하 (자기 강화 5초) | [`arin_overload.tres`](../data/skills/arin_overload.tres) |

**없다 — 그리면 창고에 쌓이는 것들.**

- **Idle / 피격 / 다운 / 공격 애니메이션.** 재생해 주는 코드가 없다.
  `Player` 가 재생하는 것은 [`WalkAnimation.ANIMATIONS`](../entities/shared/WalkAnimation.gd)
  네 개(`walk_down`/`left`/`up`/`right`)뿐이고, **멈추면 마지막 방향의 0번 프레임으로 고정**된다.
  이 게임에는 Idle 이라는 개념 자체가 없다.
- **전기 "속성".** 속성/원소 시스템이 없다. 전기는 **외형과 연출의 언어**이지 데미지 타입이 아니다.
- **각성 / 변신.** 8초 변신은 시스템이 없다. 실제 E 는 **과부하**(5초 공속 강화)이며,
  변신 연출은 §6 에서 과부하에 얹는다.
- **3타 콤보 평타.** 평타는 쿨다운 기반 단발이다(`CombatTuning.base_attack_cooldown = 0.5`).
- **지점 지정형 평타.** 낙뢰는 플레이어가 땅을 찍는 것이 아니라 **사거리 안 대상 자리**에 떨어진다.
- **창 투척 / 회수.** 평타가 낙뢰이므로 창을 던지는 동작이 게임에 없다(§7).

## 1. 기본 규격

> **[#418 에서 고쳤다]** 아래 표는 처음 값(셀 48×48 / 인물 36px / 배율 3)을 대체한다.
> 그 규격은 화면 키만 맞췄지 **디테일 예산이 기존 캐스트보다 작았다.** §1.1 참고.

| 항목 | 값 | 근거 |
|---|---|---|
| 캐릭터 셀 | **128 × 128 px** | 아래 계산 |
| 캐릭터 키(셀 안) | **108 px** | 화면 키와 같다(배율 1) |
| 셀 안 발 기준선 | **y = 120** (아래 여백 7px) | 아래 계산 |
| 시트 | **384 × 512** (3열 × 4행) | 4방향 × 3프레임 |
| `walk_sprite_scale` | **(1, 1)** | 확대하지 않는다 |
| `walk_sprite_offset` | **(0, -41)** | 아래 계산 |
| 화면 키 | **108 px** | 기존 캐스트와 동일 |
| 아웃라인 | 1px, 셀렉티브 | |
| 안티에일리어싱 | 최소한. 곡선 계단부만 1단계 | |
| 디더링 | 쓰지 않음 (전기 파티클만 예외) | |

강지도 같은 규격을 쓴다(파티 캡슐이 같다).

### 1.1 왜 128 × 128 에 배율 1 인가 — 디테일 예산이 정한다

실측한 세 값이다.

| | 네이티브 인물 높이 | 화면 키 | 도트 1개 = 화면 |
|---|---|---|---|
| 기존 캐스트(미나·설아·태희) | 약 **86 px** | 108 px | **1.25 px** |
| 처음 규격(48셀 / 36px / 배율 3) | **36 px** | 108 px | 3 px |
| **새 규격** | **108 px** | 108 px | **1 px** |
| (참고) 익룡 여왕 #405 | 72 px | 144 px | 2 px |

**기존 캐스트가 밋밋해 보이는 것은 화풍이 아니라 이 수치 때문이다.** 네이티브 86px 를
화면 108px 로 늘려 그리므로 도트가 1:1 로 떨어지지 않고, LINEAR + 밉맵으로 부드럽게 뭉갠다.

그리고 **처음 규격(36px)은 기존보다 더 거칠었다.** 얼굴에 눈·눈썹·입 셋밖에 못 넣는다고
§3 이 적어 둔 것은 화풍 선택이 아니라 그 수치에서 강제된 결과였다.

새 규격은 네이티브를 화면 키와 같게 둔다:
  - 도트 1개 = 화면 1px → **확대도 축소도 없다.** Nearest 로 크리스프하다.
  - 네이티브 108px 는 기존 캐스트(86px)보다 **25% 더 많은 픽셀**이다 —
    같은 크기로 서면서 디테일이 늘어난다.

**치비 비율은 바뀌지 않는다.** 커진 것은 해상도지 인물 비례가 아니다.
2등신 계열·납작한 단색 면·굵은 외곽선은 그대로다.

### 1.2 오프셋 계산

`walk_sprite_offset` 은 발을 충돌 캡슐 바닥(원점에서 아래로 `F = 15`)에 맞추는 값이다.
계산식은 [characters/README.md](../assets/sprites/characters/README.md) 와 같다:

```
offset.y = F / scale - (발 기준선 - 셀 높이/2)
         = 15 / 1    - (120 - 64)
         = 15        - 56
         = -41
```

배율 1 이라 `F / scale = 15` 가 그대로 정수다 — **서브픽셀 금지 원칙이 자동으로 지켜진다.**
(처음 규격이 배율 3 을 고른 이유가 `15 / scale` 을 정수로 만들기 위해서였는데,
배율 1 이면 그 제약 자체가 사라진다.)

셀 128 안에서 캐릭터가 108px 이므로 머리 위로 **13px**(y 0~12)이 남는다 — 트윈테일 들림,
고글, 과부하 부유 스파크가 들어갈 자리다.

### 1.3 늘어난 예산을 어디에 쓰는가

108px 는 36px 의 3배이고 기존 캐스트보다 25% 크다. **다만 무한하지 않다** —
선을 가늘게 그어 디테일을 늘리려 하면 화면에서 뭉친다. 늘어난 픽셀은 아래에 쓴다.

| 쓸 곳 | 이유 |
|---|---|
| **얼굴** — 코·귀·볼 홍조를 넣을 수 있다 | 36px 에서는 눈·눈썹·입뿐이었다(§3) |
| **장비 파츠** — 창을 3파츠 압축(§7)에서 풀어 창날 문양·자루 감개까지 | 24px 창이 72px 이 된다 |
| **의상 계층** — 아우터 안감, 벨트, 접힌 소매 | 실루엣을 흐리지 않는 안쪽 디테일 |
| **머리카락 결** — 2~3가닥 하이라이트 | 큰 면이라 도트가 남아돈다 |

**실루엣에는 쓰지 않는다.** 식별 요소 3개(§3)는 지금 크기로 이미 읽히고,
윤곽을 잘게 만들면 오히려 못 알아본다.

### 서브픽셀 금지 / 런타임 회전 금지

모든 파츠는 정수 픽셀 그리드에 정렬한다. 회전이 필요하면 사전 렌더 프레임을 개별 제작한다.

**단, 이 원칙은 캐릭터 스프라이트에만 적용된다.** 이펙트 쪽은 이미 절차적으로 그려지고
런타임 회전을 쓴다 — [`BeamEffect`](../entities/combat/BeamEffect.gd) 는
`rotation = direction.angle()` 이고 [`ConeEffect`](../entities/combat/ConeEffect.gd)·
[`Projectile`](../entities/combat/Projectile.gd) 은 `_draw()` 로 임의 각도를 그린다.
아린 이펙트를 스프라이트로 교체하려면 그 아키텍처를 바꾸는 이야기가 되므로 §9 의 결정 항목이다.

### 텍스처 필터 — 노드에서 Nearest 로 지정한다

`project.godot` 에 `default_texture_filter` 설정이 **없다** → 프로젝트 기본값은 **Linear** 다.
기존 시트는 0.25 로 축소해 쓰므로 Linear 가 맞고, 바꾸면 기존 캐스트가 거칠어진다.

그래서 **전역 설정을 건드리지 않는다.** 아린의 `AnimatedSprite2D` 노드에서만
`texture_filter = Nearest`(CanvasItem 속성)로 덮는다. 이걸 빼먹으면 3배 확대한 도트가
뭉개져서 픽셀 아트로 보이지 않는다 — **작업 시작 전에 확인할 첫 항목이다.**

## 2. 컬러 팔레트

### 규약: 이펙트 색은 `UITheme` 와 `tint` 에서만 온다

vfx-guide §1.4 **[확정]** — 색의 출처는 [`ui/UITheme.gd`](../ui/UITheme.gd) 이고
이펙트가 새 색을 만들지 않는다. 그리고 **아군 스킬 색은 시전자의 `CharacterData.tint`** 다.

> **형광색을 쓰지 않는다.** 이 게임의 팔레트는 흙 톤이고, 아이콘·HUD 가 전부 그 안에 있다.
> 전장만 원색이면 같은 게임으로 안 보인다. — vfx-guide §1.4

### 캐릭터 램프

**캐릭터 스프라이트 색은 `UITheme` 가 관장하지 않는다** — `UITheme` 는 UI·이펙트의 출처다.
기존 캐스트도 각자 아트 색을 갖는다(미나 금발·크림, 태희 백발·흑회). 다만 **톤이 튀지 않도록
앵커를 `UITheme` 색으로 잡고** 거기서 램프를 뽑았다.

### 이펙트 색

| 연출 | 색 | 근거 |
|---|---|---|
| 볼트 코어 | `UITheme.CREAM` `F7F3EA` | 중심은 가장 밝게 |
| 볼트 메인 | **시전자 `tint`** | vfx-guide §1.4 [확정] |
| 볼트 글로우 | `tint` 를 어둡게 | 같은 색 램프 안에서 |
| 감전(`shock_stun`) 표시 | `UITheme.LILAC` `A78BC8` | §1.4 "상태 이상(디버프)" |
| 넉백 먼지 | `UITheme.STONE_GRAY` `9A9691` | 흙·돌 톤 |
| 적이 받는 피해 숫자 | `UITheme.HOSTILE` `C8402F` | §1.4, 이미 구현됨 |

- 전기는 **3톤 고정**(코어 → 메인 → 글로우).
- 캐릭터는 파트당 **3톤 이하**, 그라데이션 금지.

### ⚠ `tint` 가 지금 빨강이다 — 결정이 필요하다

[`arin.tres`](../data/characters/arin.tres) `tint = Color(1, 0.3, 0.3)` = **`FF4D4D`**.

두 가지 문제가 있다:

1. **전기로 읽히지 않는다.** 볼트 메인이 `tint` 에서 오므로 낙뢰가 빨갛게 나간다.
2. **`HOSTILE`(`C8402F`)과 거의 같다.** 그 색은 §1.4 에서 **"적이 받는 피해"** 로 예약되어 있다.
   아군 스킬과 적 피해가 같은 빨강이면 난전에서 구분이 무너진다.

→ **`tint` 를 앰버(`D9B26A` 계열)로 바꾸는 것을 제안한다.** 전기·금속과 맞고, `HOSTILE` 과
갈리고, 흙 톤 안에 있다. 다만 `tint` 는 데이터라 이 문서가 바꾸지 않는다 — §9 결정 항목.

## 3. 캐릭터 스프라이트

### 실루엣 설계

작은 해상도에서 판독되려면 실루엣이 전부다. 아린의 식별 요소 3가지:

1. **비대칭 트윈테일** — 한쪽이 길게 흘러내림
2. **어깨의 각진 아우터** — 목 뒤로 솟은 하이칼라
3. **머리 위 고글** — 실루엣 상단의 가로선

이 3개만으로 다른 캐릭터와 구분되어야 한다. **특히 태희와 갈려야 한다** — 둘 다 원거리
계열이고 실루엣이 비슷하면 난전에서 누가 누군지 모른다.

### 얼굴 (108px 키 기준 — #418 로 예산이 늘었다)

- 눈: 세로 9px, 가로 12px
- 눈 사이 간격: 9px
- 눈썹: 3~5px 굵기, 안쪽 끝을 3px 내려 **호전적 인상**
- 입: 웃을 때 6~9px, 송곳니는 3px 흰 점 하나
- 홍채 안 하이라이트 3px, 광원 반대편
- **코·귀·볼 홍조를 넣는다** — 36px 규격에서는 자리가 없어 버렸던 것들이다(#418)

> 도트에서 표정은 **눈썹 각도**가 8할이다.
> 눈썹 안쪽 끝을 1px 내리는 것만으로 도발적인 인상이 완성된다.

108px 키에서 얼굴에 쓸 수 있는 세로가 대략 30~36px 이다. 눈·눈썹·입에 더해
코 1~2px 점, 귀 실루엣, 볼 홍조까지 들어간다.

### 애니메이션 — 지금은 워크 4방향뿐이다

| 애니메이션 이름 | 프레임 | FPS | 루프 | 상태 |
|---|---|---|---|---|
| `walk_down` | 3 | 8 | O | **필요** |
| `walk_left` | 3 | 8 | O | **필요** |
| `walk_up` | 3 | 8 | O | **필요** |
| `walk_right` | 3 | 8 | O | **필요** |

**총 12장.** 이름·프레임 수·FPS·행 순서(하/좌/상/우)는
[`WalkAnimation`](../entities/shared/WalkAnimation.gd)과 기존 시트 규약이 정한 것이라
바꿀 수 없다. **0번 프레임이 정지 포즈**다 — 멈추면 이 프레임으로 고정되므로,
0번은 서 있는 자세로 성립해야 한다(그것이 이 게임의 Idle 이다).

Idle 6f / Run 8f / Dash 4f / 평타 3타 / 스킬 8f / E 시전 10f / 피격 3f / 다운 5f 같은 세트는
**재생해 주는 코드가 없다.** 만들면 창고에 쌓인다 — §0 참고.

> 대시는 예외적으로 **기능이 있다**(`Shift`, 연속 2회). 다만 전용 애니메이션을 재생하는
> 경로가 없어 지금은 워크 프레임이 빠르게 지나갈 뿐이다. 대시 프레임을 살리려면
> `Player._process_input` 에 재생 분기를 넣는 별도 이슈가 필요하다.

### 워크 3프레임의 짜임

방향당 3프레임뿐이라 6프레임 호흡 사이클을 그대로 넣을 수 없다. 규약에 맞춘 배분:

| 프레임 | 자세 | 비고 |
|---|---|---|
| 0 | **정지 포즈** — 양발 붙고 무게 중심 중앙 | 멈춤 상태로 고정되는 프레임 |
| 1 | 왼발 앞, 몸통 +1px | |
| 2 | 오른발 앞, 몸통 +1px | 1 과 좌우 반전이 아니라 **다시 그린다** |

- 트윈테일 끝단만 **2px 진폭**으로 흔든다. 몸통보다 **1프레임 늦게** 따라오게 해서 관성을 만든다.
- 8fps 이므로 한 프레임이 0.125초다. 진폭을 크게 잡으면 덜컹거린다.
- `walk_left` 를 그린 뒤 `walk_right` 를 **좌우 반전으로 때우지 않는다** — 비대칭 트윈테일이
  식별 요소인데 반전하면 반대쪽으로 넘어가 같은 인물로 안 보인다.

## 4. 평타 — 낙뢰

출처: [`data/characters/arin.tres`](../data/characters/arin.tres)

| 값 | 수치 | 필드 |
|---|---|---|
| 사거리(원형) | **380** px | `basic_attack_range` |
| 착탄 반경 | **55** px | `basic_attack_strike_radius` |
| 거는 효과 | `shock_stun` | `basic_attack_effect_id` |
| 기절 지속 | **0.3** 초 `[확정 스펙]` | [`shock_stun.tres`](../data/status_effects/shock_stun.tres) `duration` |
| 평타 간격 | 기본 **0.5** 초 ÷ 공속 배수 | [`CombatTuning`](../entities/combat/CombatTuning.gd) `base_attack_cooldown` |

**날아가는 탄이 없다.** 사거리 안 대상의 **자리에 즉시** 원이 떨어지고 그 원 안의 적이 전부
맞는다. 빗나가지 않는 대신 조준으로 더 많이 맞힐 수 없다.

지금은 [`StrikeEffect`](../entities/combat/StrikeEffect.gd)가 도형으로 그린다.
그 주석이 왜 이 표시가 특히 필요한지 적어 두었다: *"낙뢰는 날아가는 탄이 없다. 투사체는
날아가는 동안 무엇이 일어나는지 보이지만, 낙뢰는 그 자리에 즉시 떨어지므로 표시가 없으면
원거리에서 무슨 일이 일어났는지 화면에 아무 단서가 남지 않는다."*

### 3단 구성

**① 예고 (2프레임)** — 착탄 자리 지면에 링. 안쪽으로 1px씩 수축.
`tint` 1px 링만, 채우기 없음.

**② 강하 (3프레임)** — 볼트가 위에서 착탄 지점으로 뻗는다.

- 꺾임 3~4회, 각도 불규칙
- 굵기: 코어 1px `CREAM` + 양옆 1px `tint` = 총 3px
- 분기: 2프레임째에 짧은 가지 2개 (각 2px, 도트 기준)
- **꺾임은 45° 또는 수직/수평만.** 임의 각도는 계단 현상으로 지저분해진다

```
좋음:        나쁨:
  #            #
  #             #
 #             #
 #              #
#              #
```

**③ 착탄 (4프레임)** — 방사형 스파크 6갈래, 길이 증가 후 소멸.
1프레임째만 중심에 `CREAM` 플래시. 4프레임째는 잔류 점 2~3개.

**④ 감전 (적 위, 3프레임 이내)** — `LILAC`. 맞은 적 발밑 링.

- **지속이 0.3초다.** 12fps 로 3~4프레임이 한계다. 그 안에 읽혀야 한다.
- **이동·평타·스킬이 전부 막힌다**(`blocks_movement` / `blocks_attack` / `blocks_skill` 모두 `true`).
  그래서 **"멈췄다"가 읽혀야 한다.** 움직임만 막는 상태이상과 다른 그림이어야 한다.
- **과부하 중에는 거의 끊기지 않는다.** 공속 +80% 면 평타 간격이 `0.5 / 1.8 ≈ 0.28`초라
  기절 0.3초와 겹친다 → **깜빡이지 말고 유지되는 그림**으로 그린다. 프레임마다 껐다 켜면
  과부하 중에 발작처럼 보인다.

### 착탄 원의 크기는 데이터가 정한다

vfx-guide §1.2 **[확정]** — 이펙트 지름 = 판정 지름. 착탄 원은 반경 **55px**(월드) 그대로다.
보기 좋으라고 키우거나 줄이지 않는다. 검수는 `CombatDebugLayer` 를 켜고
**디버그 원과 겹치는가**로 한다.

도트로 그릴 때 문제: 이펙트도 3배로 확대해 그리면 1 도트 = 3 월드 px 이므로
반경 55 는 **18.33 도트**다. 정수로 떨어지지 않는다.

→ `basic_attack_strike_radius` 를 **54**(= 18 도트)로 맞추면 격자에 정렬된다.
1px 차이라 밸런스 영향은 없다. 데이터 변경이므로 §9 결정 항목이다.
바꾸지 않는다면 착탄 원만 절차적(`StrikeEffect`)으로 남기고 스파크만 도트로 얹는다.

## 5. Q — 부채꼴 밀어내기

출처: [`data/skills/arin_sweep.tres`](../data/skills/arin_sweep.tres)

| 값 | 수치 | 필드 |
|---|---|---|
| 길이 | **300** px | `cone_length` |
| 각도 | **70°** (전체, 중심에서 ±35°) | `cone_angle_degrees` |
| 넉백 거리 | **220** px | `knockback_distance` |
| 피해 | **120** (신앙심 비례 아님) | `base_power`, `scales_with_faith = false` |
| 재사용 | **10.0** 초 | `cooldown` |
| 슬롯 | **Q** | `input_slot = 1` |

낙뢰가 전제하는 '거리'를 되찾는 버튼이다. 조준 방향으로 때리고 맞은 적을 바깥으로 민다.

### 연출

- **부채꼴 자체**는 [`ConeEffect`](../entities/combat/ConeEffect.gd)가 이미 절차적으로 그린다.
  각도가 조준에 따라 바뀌므로 **사전 렌더 스프라이트로 교체하지 않는다** —
  "갈래를 각도별로 N장 사전 렌더"는 이 스킬에 맞지 않는다(조준이 연속값이다).
- 도트로 얹을 것은 **부채꼴 안쪽의 볼트 결** 정도다. 타일링 가능한 1px 지그재그를
  절차적 부채꼴 위에 겹친다.
- **넉백 표현이 이 스킬의 핵심 정보다.** 도트에서 넉백은 **잔상과 먼지**로 읽힌다:
  - 적 이동 궤적에 잔상 3장 (알파 60/40/20%)
  - 지면에 먼지 퍼프 (`STONE_GRAY`, 16×8 도트, 3프레임)
  - **밀려나는 시간은 0.15초다**([`EnemyBase`](../entities/enemies/EnemyBase.gd) `KNOCKBACK_DURATION`).
    12fps 로 두 프레임이 채 안 되므로 잔상은 **순차 프레임이 아니라 동시에 뜨는 유령 3장**이어야
    한다. 프레임을 나눠 그리면 넉백이 끝난 뒤에 잔상이 뜬다
  - 220px 를 0.15초에 밀어내므로 궤적이 길고 빠르다 — 잔상 간격을 넓게 잡는다
  - 넉백 방향은 조준 방향이 아니라 **시전자에서 대상으로 향하는 벡터**다(`arin_sweep.tres` 설명).
    정면의 적은 곧게, 가장자리의 적은 비스듬히 밀려난다 — 먼지 방향도 그에 맞춘다

## 6. E — 과부하

출처: [`data/skills/arin_overload.tres`](../data/skills/arin_overload.tres),
[`overload.tres`](../data/status_effects/overload.tres)

| 값 | 수치 | 필드 |
|---|---|---|
| 지속 | **5.0** 초 `[확정 스펙]` | `overload.tres` `duration` |
| 공속 | **+80%** `[임시값]` | 같은 파일 `stat_percent.attack_speed` |
| 동반 효과 | `overload_reach` (사거리 제한 해제) | 같은 파일 `also_apply_effect_id` |
| 재사용 | **22.0** 초 | `arin_overload.tres` `cooldown` |
| 슬롯 | **E** | `input_slot = 2` |
| 피해 | 없음 (순수 자기 강화) | `base_power = 0` |

**"각성" 연출은 이 스킬에 얹는다.** 8초가 아니라 **5초**이고, 변신이 아니라 **과부하**다 —
공속이 올라 낙뢰가 쏟아지고 사거리 제한이 풀린다. 방향은 같다: **한 단계 밝아지고,
스파크가 붙고, 끝날 때 방전된다.**

### 시전 순간 (3프레임)

10프레임 시전 연출은 재생 코드가 없다(§0). 대신 **이펙트 노드로 3프레임**을 쓴다.

| 프레임 | 내용 |
|---|---|
| 1 | 흰(`CREAM`) 실루엣 1프레임 — 전신 |
| 2 | 방사형 링 웨이브 확산 시작 |
| 3 | 링이 커지며 페이드 |

> 1프레임째 **흰색 실루엣 한 장**이 임팩트의 절반을 담당한다.

### 과부하 중 외형 (5초)

**팔레트 스왑** — 스프라이트를 새로 그리지 않고 램프를 한 단계씩 밀어올린다.

| 원본 | 과부하 |
|---|---|
| 머리 메인 `D9B26A` | `F7F3EA` |
| 머리 섀도 `A8823F` | `D9B26A` |
| 눈 홍채 `D9B26A` | `F7F3EA` |
| 의상 다크 `3B342B` | `4A4234` |

**오버레이 (별도 레이어)**

| 요소 | 사양 |
|---|---|
| 부유 스파크 | 캐릭터 주변 랜덤 1px 점 **4~6개**, 4프레임 루프 |
| 눈 발광 | 눈 주변 1px `CREAM` 글로우 |
| 발밑 아우라 링 | 발밑 타원 링, 2프레임 깜빡임 |

**머리카락 부유는 넣지 않는다.** 프레임별 재작화가 필요한데 워크가 방향당 3프레임뿐이라
4방향 × 3프레임을 과부하용으로 한 벌 더 그려야 한다(12장 추가). 값이 비싸다 — 필요해지면 별도 이슈.

### 키라키라 요령

도트에서 반짝임은 **크기가 아니라 타이밍**이다.

- 스파크 점은 **절대 동시에 켜지 않는다.** 프레임마다 다른 점이 켜진다
- `1px 점 → 십자 3px → 1px 점` 3프레임 유닛을 만들고, 랜덤 위치·랜덤 시작 프레임으로 뿌린다
- 점 개수는 **6개 이하.** 많으면 지저분해진다

### 종료 예고

지속 **2초** 전부터 스파크를 6 → 4 → 2 로 줄인다(5초 지속이므로 짧게).
종료 순간 방전 3프레임.

> 남은 시간을 읽을 API 가 지금 없다. `StatusEffectSystem` 에 남은 지속을 묻는 함수가
> 필요하다 — §9 결정 항목.

## 7. 무기 — 창

### 창은 **들고 있는 소품**이다

아린의 평타는 **낙뢰**이고 던지는 동작이 게임에 없다(§0).
따라서 창 투척·회수·8방향 회전·비행 트레일은 붙을 자리가 없다.

→ 창은 **워크 프레임 안에서 손에 들린 채로** 그린다. 별도 스프라이트도, 회전 프레임도 만들지 않는다.

### 108px 키에서의 창 설계 (#418 로 예산이 늘었다)

| 파트 | 도트 | 색 |
|---|---|---|
| 전체 길이 | 72px | |
| 창날 | 21px, 이엽 | 의상 다크 + `tint` 코어 |
| 코어 슬릿 | 창날 중앙 3px | `CREAM` |
| 창날 문양 | 1px 각인 2~3획 | `tint` — 72px 라 들어간다 |
| 부유 링 | 6px 원 1개 | `tint` |
| 자루 | 45px, 3px 굵기 | 의상 다크 |
| 자루 감개 | 3~4곳 가로 1px 띠 | 의상 다크 섀도 |
| 자루 라인 | 3px 세로선 | 이너 헤어 `6B8FA8` |

- 파츠는 **5개**까지 간다(창날 / 문양 / 링 / 자루 / 감개). 처음 규격에서 3개로 압축했던 것을
  #418 로 푼다 — 72px 이면 각인과 감개가 화면에서 읽힌다
- 부유 링은 **자루와 3px 떨어뜨려** 그려야 "떠 있음"이 읽힌다
- 발광부는 여전히 **창날 코어와 링만.** 늘어난 예산을 발광에 쓰면 실루엣이 무너진다
- 대각선 배치는 45° 고정

### 과부하 중 창

| 요소 | 변화 |
|---|---|
| 코어 슬릿 | `tint` → `CREAM` |
| 자루 라인 | 발광 (`6B8FA8` → `F7F3EA`) |
| 부유 링 | 2프레임 깜빡임 |

회전 애니메이션은 넣지 않는다(런타임 회전 금지 + 프레임 예산).

## 10. 작업 순서

1. **§9 의 1번(tint) 을 먼저 정한다** — 이펙트 색 전부가 여기서 나온다. 흔들리면 다시 그린다
2. **텍스처 필터 확인** — `AnimatedSprite2D.texture_filter = Nearest`. 이걸 빼먹으면 뭉개진다
3. **`walk_down` 0번 프레임** — 실루엣과 얼굴 확정. **이 게임의 Idle 이 이 한 장이다**
4. `walk_down` 3프레임 완성
5. `walk_left` 3프레임 (측면 실루엣 확정)
6. `walk_up` / `walk_right` (반전 금지)
7. 시트 조립 + `arin.tres` 연결 → **여기서 전장에 세워 보고 크기·발 위치를 확인한다**
8. 낙뢰 3단 세트 (예고 → 강하 → 착탄) + 감전 링
9. 부채꼴 볼트 결 + 넉백 먼지
10. 과부하 팔레트 스왑 + 오버레이 + 종료 방전

> 3번까지 끝나면 캐릭터의 인상이 결정된다.
> 여기서 만족스럽지 않으면 뒤로 진행하지 말고 되돌아갈 것.
>
> 7번을 8번보다 먼저 두는 이유: 화면에 세워 보지 않고 이펙트로 넘어가면, 캐릭터 키가
> 어긋난 것을 이펙트를 다 그린 뒤에 발견한다. 108px·발 위치·필터를 눈으로 확인하고 넘어간다.
