# 스킬 이펙트 공백 정리 + Codex 프롬프트 (#387)

**16개 스킬 중 10개가 전용 연출이 없다.** 무엇이 비었는지 정리하고, 그중 아트로 메울 수 있는 것의
Codex 프롬프트를 담는다.

> **먼저 읽을 것**: 이펙트 규약의 정본은 [vfx-guide.md](vfx-guide.md)(#262)다. 색·판정 지름·
> 부모 노드·움직임 어휘는 거기가 소유한다. 이 문서는 그 위에 "무엇이 비었는가"만 얹는다.
>
> **아트만 만들면 화면에 안 나온다.** 아래 10개 중 대부분은 그릴 것이 없어서가 아니라
> **스폰하는 코드가 없어서** 비어 있다. §3 에서 아트로 풀 것과 배선으로 풀 것을 나눴다.

### 특히 나쁜 세 자리

1. **강지 E 불가침** — 쿨타임 **45초**짜리 **3초 무적**인데 아무 표시가 없다.
   걸렸는지 확인할 방법이 없어서, 플레이어는 이 버튼이 동작하는지조차 모른다.
2. **하랑 Q 도발** — 반경 **260px** 즉발 원. 그 원이 화면에 안 그려지므로
   **누가 도발에 걸렸는지는 보이는데(StatusRing) 어디까지 걸렸는지가 안 보인다.**
3. **회복 전부** — `DamageNumberSpawner` 는 `damage_taken` 만 듣는다(`DamageNumberSpawner.gd:17`).
   `EventBus.healing_applied` 를 **듣는 곳이 아예 없다.** 회복 스킬 3종이 숫자도 연출도 없이 동작한다.

### 신호는 쏘는데 받는 곳이 없는 것

- `EventBus.skill_shield_burst` — 미나 E 가 터질 때 쏘지만(`Player.gd:1601`) **리스너가 0개**다.
- `EventBus.healing_applied` — 위와 같다.

둘 다 **연출을 붙일 자리가 이미 뚫려 있다는 뜻**이다. 새 신호를 만들 필요가 없다.

## 2. 움직임 어휘 점검 (vfx-guide §7)

§7 은 "같은 움직임을 두 사건에 쓰면 색만으로 구분해야 하고, 전투 중에는 색을 읽을 시간이 없다"고 못박았다.
아래는 **이미 쓰이는 움직임**이다:

| 노드 | 움직임 |
|---|---|
| `Shockwave` (설아 Q) | 밖으로 **퍼진다**(이동한다) |
| `ChainArc` (태희 Q 튕김) | 두 점을 **잇는다** |
| `BeamEffect` (태희 E) | 한 방향으로 **뻗는다** |
| `AuraZone` (강지 Q) | 그 자리에 **머문다**(지대) |
| `StatusRing` | 발밑에 **머문다**(상태) |
| `ExecuteMark` | 안으로 **조여든다** |
| `ConeEffect` (아린 Q) | 부채꼴로 **휩쓴다** |
| `StrikeEffect` (아린 평타) | 위에서 **떨어진다** |
| `OverloadEffect` (아린 E) | 시전자를 **감싼다** |

새로 만들 움직임은 이 아홉과 겹치면 안 된다. §3 에서 고른 것:

| 새 움직임 | 쓰는 곳 | 겹치지 않는 이유 |
|---|---|---|
| **터진다** (제자리, 한 번에) | 폭발 3종 | `Shockwave` 는 **이동**한다. 폭발은 제자리에서 한 번에 끝난다 |
| **차오른다** (아래→위) | 회복 | 위로 가는 움직임을 아무도 안 쓴다 |
| **번쩍인다** (켜졌다 꺼짐) | 하랑 Q | 퍼지지도 머물지도 않는다. 즉발 1회를 그대로 옮긴 것 |
| **금이 간다** (갈라짐) | 하랑 E | `OverloadEffect`(감싼다)와 갈린다 — 하랑도 자기 강화지만 그림이 달라야 한다 |
| **굳는다** (껍질) | 강지 E | 정지·경질. `StatusRing`(얇은 링)과 두께로 갈린다 |

## 3. 아트로 풀 것 / 배선으로 풀 것

**이 구분이 이 문서의 핵심이다.** 아트를 만들어도 스폰하는 코드가 없으면 화면에 안 나온다.

### 3-A. 아트가 필요한 것 (§4 에 프롬프트)

| # | 대상 | 필요한 코드 |
|---|---|---|
| 1 | **폭발** — 미나 Q 방울(r70) · 미나 E 보호막(r90) · 태희 4타(r100) | `Projectile._explode()` 와 `_detonate_skill_shield()` 에서 스폰. **공용 1종**을 반경으로 스케일 |
| 2 | **회복** — 미나 패시브 · 설아 triage · 강지 수혈 | `EventBus.healing_applied` 리스너 노드 하나. **공용 1종** |
| 3 | **도발 원** — 하랑 Q (r260) | `_cast_instant_aoe()` 에서 스폰 |
| 4 | **격노 균열** — 하랑 E | `_cast_self_effect()` 의 아린 전용 분기(`Player.gd:1192`)를 데이터로 일반화 |
| 5 | **불가침 껍질** — 강지 E | `_cast_ally_effect()` 에서 대상에게 붙임 |

**1·2 는 공용이다.** 세 스킬이 같은 사건(폭발 / 회복)을 일으키므로 그림을 따로 그리면
같은 일이 셋 다르게 보인다 — vfx-guide §7 이 경계하는 바로 그 상황이다.

### 3-B. 아트가 아니라 기존 것을 고치는 게 맞는 것

| 대상 | 왜 아트가 아닌가 |
|---|---|
| **설아 E 강화**(파티 전체 버프) | `StatusRing` 이 이미 발밑 링을 그리는데 `is_debuff` 인 것만 거른다(`StatusRing.gd:94`). **버프까지 확장**하고 스타일만 다르게 주는 것이 맞다. 새 노드를 만들면 발밑에 두 종류 링이 생긴다 |
| **강지 지대 버프**(`gangji_zone`) | 위와 같다. 지대(AuraZone)는 보이는데 **그 안에서 버프를 받고 있는지**가 안 보인다 |
| **회복 숫자** | `DamageNumberSpawner` 에 `healing_applied` 분기를 더하면 된다. 색은 `UITheme.POSITIVE`(§1.4 에 이미 지정) |
| **태희 Q 시전 순간** | 5초 창이 열렸다는 사실은 **HUD 의 일**이지 전장 연출이 아니다 |
| **하랑 E 평타 대체 광역**(r120) | 3-A 의 **폭발 공용 스프라이트를 재사용**한다. 새로 그리지 않는다 |

## 4. Codex 프롬프트

각 프롬프트는 **자기 완결적**이다 — Codex 는 이 저장소를 읽지 않는다.

**공통 전제**: 이 게임의 이펙트는 전부 절차적 `_draw()` 이고 **텍스처를 쓰는 이펙트가 하나도 없다.**
아래 산출물은 그 절차적 도형을 **대체하는 것이 아니라 그 위에 얹는 도트 오버레이**다
(`docs/arin-pixel-art-design.md` §9-4 가 같은 결론을 내렸다 — 반경·각도가 연속값이라 사전 렌더로
완전히 대체할 수 없다).

### 프롬프트 A — 폭발 · 회복 (공용 2종)

```
2D 픽셀 아트 이펙트 스프라이트 시트 2종을 만들어 줘. 흙 톤 팔레트의 게임이야.

[공통 규격]
- 네이티브 해상도로 내보내고 업스케일하지 마. 투명 배경(RGBA).
- 안티에일리어싱 금지. 아래 팔레트 색 외의 중간색을 만들지 마.
- 애니메이션은 12fps 기준. 프레임을 가로로 나열한 시트 1장씩.
- 방사 대칭으로 그려. 게임이 반경에 맞춰 확대·축소해서 쓸 거야.

[팔레트 — 이 6색만]
밝은 중심 #F7F3EA
적대(피해) #C8402F
적대 섀도 #8E2E22
회복 #6F8A46
회복 밝음 #9DBF6E
먼지 #9A9691
형광색·원색을 절대 넣지 마. 그라데이션 금지.

[1) 폭발 — 4프레임, 각 64x64]
제자리에서 한 번에 터지고 끝나는 폭발이야. **밖으로 이동하지 않아** —
이 게임엔 이미 "퍼져 나가는 파동"이 따로 있어서, 그것과 구분돼야 해.
  프레임 1: 중심에 #F7F3EA 원(지름 16). 그 둘레 1px 링(지름 40) #C8402F.
  프레임 2: 중심 원이 줄고(지름 8), 링이 지름 56 으로 커지며 굵기 2px.
            링에서 바깥으로 삐죽한 조각 8개(각 3~4도트, 45도 간격).
  프레임 3: 중심 사라짐. 링이 지름 62, 1px, #8E2E22 로 어두워짐. 조각이 링에서 떨어져 나감.
  프레임 4: 링 없음. 떨어져 나간 조각 8개만 남아 흩어짐. 아래쪽 2개에 #9A9691 먼지 점.
- 가장 큰 원이 프레임 3 에서 지름 62 여야 해(64 캔버스 안에 1px 여유).
- 링은 정원이어야 하고, 픽셀 계단은 브레젠험 원처럼 규칙적으로.

[2) 회복 — 4프레임, 각 48x64]
캐릭터 발밑에서 위로 차오르는 빛이야. **아래에서 위로** 올라가야 해 —
이 게임의 다른 연출은 전부 밖으로 퍼지거나 제자리에 머물러서, 위로 가는 움직임이 비어 있어.
  프레임 1: 발밑(캔버스 아래 1/4)에 눌린 타원 링(가로 32 세로 10) #6F8A46, 1px.
  프레임 2: 타원에서 위로 짧은 세로선 5개(각 6도트) #9DBF6E. 길이가 서로 달라야 해.
  프레임 3: 세로선이 위로 올라가며 끊긴 점들이 됨. 타원이 옅어짐.
  프레임 4: 캔버스 위쪽에 점 3~4개만 남고 소멸.
- **깜빡이지 말 것.** 네 프레임이 하나의 연속된 상승으로 읽혀야 해.
- 십자 반짝임(+ 모양)을 쓰지 마. 그건 다른 연출이 이미 쓰고 있어.
```

### 프롬프트 B — 하랑 (도발 원 · 격노 균열)

```
2D 픽셀 아트 이펙트 2종을 만들어 줘. 흙 톤 팔레트 게임의 탱커 캐릭터 스킬이야.
```

### 프롬프트 C — 강지 불가침 껍질


## 5. 산출물이 오면 — 붙이는 순서

**아트만으로는 아무것도 화면에 안 나온다.** 각 항목에 코드 한 자리가 따라붙는다(§3-A 표).

붙이는 순서는 **값싸고 효과 큰 것부터** — vfx-guide §4 "2단계"와 같은 원칙이다.

1. **회복 숫자** — `DamageNumberSpawner` 에 `healing_applied` 분기. 아트 없이도 즉시 효과가 크다.
2. **회복 연출** — 위 리스너에 프롬프트 A-2 를 얹는다. 스킬 3개가 한 번에 채워진다.
3. **폭발** — `Projectile._explode()` 한 자리. 스킬 3개가 한 번에 채워진다.
4. **강지 E 껍질** — 공백 중 가장 나쁜 자리(45초 쿨 무적이 안 보인다).
5. **하랑 Q 원 → E 균열** — 연출이 하나도 없는 유일한 캐릭터를 채운다.
6. **StatusRing 을 버프까지 확장**(§3-B) — 설아 E·강지 지대가 함께 해결된다.

> 3 번을 4 번보다 앞에 두는 이유: 한 자리를 고치면 세 스킬이 채워지는데, 강지 E 는 한 자리에 하나다.
> 다만 **개별 심각도는 강지 E 가 가장 크다** — 급하면 순서를 바꿔도 된다.

각 항목마다 별도 이슈로 쪼갠다. 이 문서는 정리와 프롬프트까지다.
