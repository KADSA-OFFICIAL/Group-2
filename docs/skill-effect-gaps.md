# 스킬 이펙트 공백 정리 + Codex 프롬프트 (#387)

**16개 스킬 중 10개가 전용 연출이 없다.** 무엇이 비었는지 정리하고, 그중 아트로 메울 수 있는 것의
Codex 프롬프트를 담는다.

> **먼저 읽을 것**: 이펙트 규약의 정본은 [vfx-guide.md](vfx-guide.md)(#262)다. 색·판정 지름·
> 부모 노드·움직임 어휘는 거기가 소유한다. 이 문서는 그 위에 "무엇이 비었는가"만 얹는다.
>
> **아트만 만들면 화면에 안 나온다.** 아래 10개 중 대부분은 그릴 것이 없어서가 아니라
> **스폰하는 코드가 없어서** 비어 있다. §3 에서 아트로 풀 것과 배선으로 풀 것을 나눴다.

1. **강지 E 불가침** — 쿨타임 **45초**짜리 **3초 무적**인데 아무 표시가 없다.

### 신호는 쏘는데 받는 곳이 없는 것

- `EventBus.skill_shield_burst` — 미나 E 가 터질 때 쏘지만(`Player.gd:1601`) **리스너가 0개**다.
- `EventBus.healing_applied` — 위와 같다.

둘 다 **연출을 붙일 자리가 이미 뚫려 있다는 뜻**이다. 새 신호를 만들 필요가 없다.

## 2. 움직임 어휘 점검 (vfx-guide §7)

§7 은 "같은 움직임을 두 사건에 쓰면 색만으로 구분해야 하고, 전투 중에는 색을 읽을 시간이 없다"고 못박았다.
아래는 **이미 쓰이는 움직임**이다:

| 노드 | 움직임 |
|---|---|
| `Shockwave` (설아 Q) | 밖으로 **퍼진다**(이동한다) |
| `ChainArc` (태희 Q 튕김) | 두 점을 **잇는다** |
| `BeamEffect` (태희 E) | 한 방향으로 **뻗는다** |
| `AuraZone` (강지 Q) | 그 자리에 **머문다**(지대) |
| `StatusRing` | 발밑에 **머문다**(상태) |
| `ExecuteMark` | 안으로 **조여든다** |
| `ConeEffect` (아린 Q) | 부채꼴로 **휩쓴다** |
| `StrikeEffect` (아린 평타) | 위에서 **떨어진다** |
| `OverloadEffect` (아린 E) | 시전자를 **감싼다** |

새로 만들 움직임은 이 아홉과 겹치면 안 된다. §3 에서 고른 것:

| 새 움직임 | 쓰는 곳 | 겹치지 않는 이유 |
|---|---|---|
| **터진다** (제자리, 한 번에) | 폭발 3종 | `Shockwave` 는 **이동**한다. 폭발은 제자리에서 한 번에 끝난다 |
| **차오른다** (아래→위) | 회복 | 위로 가는 움직임을 아무도 안 쓴다 |
| **번쩍인다** (켜졌다 꺼짐) | 하랑 Q | 퍼지지도 머물지도 않는다. 즉발 1회를 그대로 옮긴 것 |
| **금이 간다** (갈라짐) | 하랑 E | `OverloadEffect`(감싼다)와 갈린다 — 하랑도 자기 강화지만 그림이 달라야 한다 |
| **굳는다** (껍질) | 강지 E | 정지·경질. `StatusRing`(얇은 링)과 두께로 갈린다 |

## 3. 아트로 풀 것 / 배선으로 풀 것

**이 구분이 이 문서의 핵심이다.** 아트를 만들어도 스폰하는 코드가 없으면 화면에 안 나온다.

### 3-A. 아트가 필요한 것 (§4 에 프롬프트)

| # | 대상 | 필요한 코드 |
|---|---|---|
| 1 | **폭발** — 미나 Q 방울(r70) · 미나 E 보호막(r90) · 태희 4타(r100) | `Projectile._explode()` 와 `_detonate_skill_shield()` 에서 스폰. **공용 1종**을 반경으로 스케일 |
| 2 | **회복** — 미나 패시브 · 설아 triage · 강지 수혈 | `EventBus.healing_applied` 리스너 노드 하나. **공용 1종** |
| 3 | **도발 원** — 하랑 Q (r260) | `_cast_instant_aoe()` 에서 스폰 |
| 4 | **격노 균열** — 하랑 E | `_cast_self_effect()` 의 아린 전용 분기(`Player.gd:1192`)를 데이터로 일반화 |
| 5 | **불가침 껍질** — 강지 E | `_cast_ally_effect()` 에서 대상에게 붙임 |

**1·2 는 공용이다.** 세 스킬이 같은 사건(폭발 / 회복)을 일으키므로 그림을 따로 그리면
같은 일이 셋 다르게 보인다 — vfx-guide §7 이 경계하는 바로 그 상황이다.

### 3-B. 아트가 아니라 기존 것을 고치는 게 맞는 것

| 대상 | 왜 아트가 아닌가 |
|---|---|
| **설아 E 강화**(파티 전체 버프) | `StatusRing` 이 이미 발밑 링을 그리는데 `is_debuff` 인 것만 거른다(`StatusRing.gd:94`). **버프까지 확장**하고 스타일만 다르게 주는 것이 맞다. 새 노드를 만들면 발밑에 두 종류 링이 생긴다 |
| **강지 지대 버프**(`gangji_zone`) | 위와 같다. 지대(AuraZone)는 보이는데 **그 안에서 버프를 받고 있는지**가 안 보인다 |
| **회복 숫자** | `DamageNumberSpawner` 에 `healing_applied` 분기를 더하면 된다. 색은 `UITheme.POSITIVE`(§1.4 에 이미 지정) |
| **태희 Q 시전 순간** | 5초 창이 열렸다는 사실은 **HUD 의 일**이지 전장 연출이 아니다 |
| **하랑 E 평타 대체 광역**(r120) | 3-A 의 **폭발 공용 스프라이트를 재사용**한다. 새로 그리지 않는다 |

## 4-A. Codex 스크립트로 뽑는 경로

### 왜 이미지 생성이 아니라 스크립트인가

이 저장소에서 Codex 로 만든 선례는 [`tools/gen_icons.py`](../tools/gen_icons.py)(#289)다 —
Pillow 로 아이콘을 **그리는 파이썬 스크립트**이지 생성된 이미지가 아니다. 이펙트도 같은 형태로 간다.

이유는 셋이다.

1. **판정 지름에 맞춰 확대·축소된다.** vfx-guide §1.2 [확정] 이 "이펙트 지름 = 판정 지름"을 요구하는데,
   반경은 스킬마다 다르고(70 / 90 / 100 / 120 / 260) 데이터가 바뀌면 또 달라진다.
   **손으로 그린 도트는 이 연속적인 배율을 못 견딘다** — 정수배가 아니면 뭉개진다.
   `gen_icons.py` 처럼 4배로 그려 축소하면 어떤 배율에서도 깨끗하다.
2. **수치가 데이터에서 온다.** 링 굵기·조각 개수·프레임 수를 스크립트 상수로 두면
   화면에서 보고 고칠 때 **한 줄만 바꿔 다시 뽑는다.** 그림을 다시 그리지 않는다.
3. **팔레트를 어길 수 없다.** 색을 상수로 박으면 생성 모델이 흙 톤 밖으로 새는 일이 없다.
   vfx-guide §1.4 가 "이펙트가 새 색을 만들지 않는다"고 [확정] 했다.

> **캐릭터 워크 시트는 이 방법을 쓸 수 없다.** 얼굴이 있는 치비 스프라이트는 Pillow 도형으로
> 못 그린다 — 그쪽은 이미지 생성이 맞다([pixel-art-prompts.md](pixel-art-prompts.md)).
> 이펙트는 원·링·직선·다각형뿐이라 코드로 그리는 편이 낫다.

### 프롬프트 (Codex 에 그대로 붙여 넣는다)

````
파이썬 + Pillow 로 게임 이펙트 스프라이트 시트를 생성하는 스크립트를 만들어 줘.
파일 경로: tools/gen_effects.py

이 저장소에는 이미 같은 형태의 선례가 있어: tools/gen_icons.py.
그 파일의 구조를 그대로 따라 줘 — 4배 크기(WORK_SIZE)로 그린 뒤 LANCZOS 로 축소해서
저장하고, 색은 모듈 상수로 두고, main() 에서 각 산출물을 저장하는 방식.
가능하면 그 파일을 열어 읽고 헬퍼(polygon / ellipse / line 같은 것)의 이름과 서명을 맞춰 줘.

## 왜 4배로 그려 축소하나 (지우지 말 것)
게임이 이 스프라이트를 **판정 반경에 맞춰 확대·축소**한다. 반경은 스킬마다 다르고
(70 / 90 / 100 / 120 / 260 월드 px) 나중에 밸런스로 또 바뀐다. 정수배가 아닌 배율이
반드시 생기므로 하드 픽셀로 그리면 뭉개진다. 슈퍼샘플링해서 부드러운 가장자리로 두는 것이 맞다.

## 색 — 정확히 이 상수만 쓸 것. 새 색을 만들지 마
게임의 팔레트는 흙 톤이고 UI 전체가 그 안에 있어. 형광색·채도 높은 원색을 넣으면
전장만 다른 게임처럼 보여. 아래는 게임의 UITheme 에서 그대로 가져온 값이야.

OUTLINE    = "#6E6558"
CREAM      = "#F7F3EA"   # 밝은 면·하이라이트
STONE_GRAY = "#9A9691"   # 먼지·돌
STONE_DARK = "#6E6A64"
AMBER      = "#D9B26A"   # 금속·강조
LILAC      = "#A78BC8"   # 상태이상(디버프) 전용
HOSTILE    = "#C8402F"   # 적이 받는 피해
POSITIVE   = "#6F8A46"   # 회복
SKY        = "#6B8FA8"   # 탱커 역할색
LEAF       = "#7B9455"   # 버퍼 역할색
INK        = "#2E2A24"

파생색이 필요하면 위 색을 OUTLINE 쪽으로 섞어서 만들고, 주석에 어느 색에서 왔는지 적어 줘
(gen_icons.py 의 SAND_DARK 가 그렇게 하고 있어).

## 공통 규격
- 모든 산출물은 RGBA PNG, 투명 배경.
- 애니메이션은 **가로로 프레임을 나열한 시트 1장**. 프레임 폭이 전부 같아야 하고,
  게임이 균등 격자로 자를 거라 여백을 프레임마다 다르게 주면 안 돼.
- 12fps 재생 기준으로 프레임 수를 잡았어.
- 저장 위치: assets/sprites/effects/  (없으면 만들어)
- 각 시트를 저장할 때 경로와 크기를 print 해 줘 (gen_icons.py 의 save_icon 처럼).
- 원과 링은 정원이어야 해. 타원이 필요한 곳은 명시했어.
- **그림자·글로우·그라데이션을 쓰지 마.** 단색 면 + 뚜렷한 윤곽선이야.

## 만들 것 — 5종

### 1) burst.png — 폭발 (4프레임, 프레임당 128x128)
쓰는 곳: 세 스킬이 공유한다(반경 70 / 90 / 100 의 광역 폭발). 게임이 반경에 맞춰 스케일해.
그래서 **캔버스 중심 기준 방사 대칭**으로, 최대 지름이 프레임 3 에서 정확히 124 여야 해
(128 안에 2px 여유).

움직임은 **제자리에서 한 번에 터지고 끝난다**여야 해. 밖으로 이동하면 안 돼 —
이 게임엔 이미 "퍼져 나가며 이동하는 파동"이 따로 있어서 그것과 구분돼야 해.

  프레임 1: 중심에 CREAM 원(지름 32). 그 둘레에 HOSTILE 링(지름 72, 굵기 4).
  프레임 2: 중심 원 지름 16 으로 축소. 링 지름 104, 굵기 6, HOSTILE.
            링에서 바깥으로 삐죽한 삼각 조각 8개(45도 간격, 각 길이 10).
  프레임 3: 중심 원 없음. 링 지름 124, 굵기 2, 색을 HOSTILE 을 INK 쪽으로 40% 섞은 어두운 값.
            조각 8개는 링 **위에** 걸쳐 놓아(떨어져 나오는 중). 링 바깥으로 내보내지 마 —
            링이 이미 지름 124 라서 캔버스(128)를 넘어간다.
  프레임 4: 링 없음. 조각 8개만 중심에서 반경 56 자리에 남고 크기가 절반(길이 5).
            아래쪽 3개는 STONE_GRAY 로.

  ※ 어느 프레임에서도 그려지는 것이 캔버스 128 을 넘지 않아야 해.
    프레임 2 가 가장 빠듯해: 링 지름 104 + 조각이 양쪽으로 10 씩 = 124. 여기 맞춰 검산해 줘.

### 2) heal.png — 회복 (4프레임, 프레임당 64x96)
쓰는 곳: 회복 스킬 3종이 공유한다. 캐릭터 발밑에 놓여.
움직임은 **아래에서 위로 차오른다**여야 해 — 이 게임의 다른 연출은 전부 밖으로 퍼지거나
제자리에 머물러서, 위로 가는 움직임이 비어 있어. 그게 이 연출의 식별점이야.

캔버스 아래쪽(y=80 근처)이 발밑이야.

  프레임 1: 발밑에 눌린 타원 링(가로 44, 세로 14, 굵기 2, POSITIVE). 그 외 없음.
  프레임 2: 타원 유지. 타원 위로 세로선 5개, 굵기 2, POSITIVE 를 CREAM 쪽으로 40% 섞은 밝은 값.

- **깜빡이지 말 것.** 네 프레임이 하나의 연속된 상승으로 읽혀야 해.
- 십자(+) 반짝임을 쓰지 마. 다른 연출이 이미 쓰고 있어.

### 3) taunt_ring.png — 도발 원 (3프레임, 프레임당 256x256)
쓰는 곳: 탱커의 즉발 스킬. 반경 260 월드 px 의 원 안에 있는 적이 한 번에 걸려.

움직임은 **한 번에 켜졌다 꺼진다**여야 해. 퍼지지도 머물지도 않아 —
실제로 이 스킬은 순간에 판정이 끝나거든. 링 지름이 세 프레임 내내 **같아야 해.**
커지면 파동으로 읽혀서 다른 스킬과 헷갈려.

  프레임 1: 지름 248 정원 링, 굵기 8, LEAF. 안쪽은 비워 둬(채우면 캐릭터가 가려져).
  프레임 2: 같은 지름, 굵기 3, CREAM.
            링 위에 **안쪽을 향한** 짧은 갈고리 8개(45도 간격, 각 길이 14, 굵기 3, LEAF).
            갈고리는 링에서 중심 쪽으로 뻗되 45도로 한 번 꺾여. 끌어당긴다는 뜻이야.
  프레임 3: 같은 지름, 굵기 2, OUTLINE. 링을 24등분해서 한 칸 걸러 지워 점선으로. 갈고리 없음.

### 4) rage_crack.png — 격노 균열 (4프레임, 프레임당 96x128)
쓰는 곳: 체력 30% 아래에서만 켜지는 탱커의 발악 버프. 캐릭터에게 붙어.
움직임은 **주변 공간이 갈라진다**여야 해. 감싸는 그림으로 만들지 마 —
다른 캐릭터의 자기 강화가 이미 "감싼다"를 쓰고 있어서 겹쳐.

**캔버스 중앙의 24x40 영역(캐릭터가 서는 자리)은 반드시 비워 둬.** 몸을 가리면 안 돼.

  프레임 1: 그 빈 영역 바깥에 균열 3개. 각 길이 12~20, 굵기 2, HOSTILE.
  프레임 2: 균열 5개, 길이 20~32. 각 균열 안쪽에 CREAM 코어 선(굵기 1).

  임의 각도는 계단이 지저분해지고, 이 게임의 전기 연출도 같은 규칙을 쓰고 있어.
- 균열 위치는 재현 가능해야 해 — random 을 쓸 거면 모듈 상단에서 고정 시드를 줘.

### 5) immunity_shell.png — 불가침 껍질 (5프레임, 프레임당 96x128)
쓰는 곳: 쿨타임 45초짜리 3초 무적 버프. 지금 화면에 아무 표시가 없어서 플레이어가

  프레임 1: 캐릭터 자리(중앙 24x40) 바깥에 정육각형 판 6개가 흩어져 있음.
            각 한 변 8, 윤곽 굵기 2 SKY, 면은 비움.

            맞물린 이음새 6곳에 CREAM 점(3x3).

            SKY 를 OUTLINE 쪽으로 35% 섞은 어두운 값으로.

- 프레임 4~5 를 번갈아 루프해서 지속을 표현할 거야. 1~3 은 걸리는 순간 1회 재생.
- **껍질 윤곽 4px 가 이 연출의 요점이야.** 얇게 하면 기존 상태 링과 구분이 안 돼.

## 마지막으로
- 스크립트를 실제로 실행해서 5개 PNG 가 나오는지 확인하고, 각 시트의 크기가
  (프레임폭 x 프레임수) x 프레임높이 인지 검산해 줘.
````

## 4-B. ChatGPT 이미지 생성으로 뽑는 경로

Codex 를 쓸 수 없을 때의 대안이다. **§4 의 스크립트 경로가 더 낫다** — 아래 한계를 알고 쓴다.

### 무엇을 잃는가

| | 스크립트(§4) | ChatGPT 이미지 생성 |
|---|---|---|
| 반경에 맞춘 확대·축소 | 4배로 그려 축소 → 어떤 배율에서도 깨끗 | 배율이 어긋나면 뭉개진다 |
| 굵기·개수 수정 | 상수 한 줄 고쳐 다시 뽑음 | 처음부터 다시 그림 |
| 팔레트 | 상수라 어길 수 없음 | 비슷한 색조로 수백 색이 섞여 나옴 |
| 재현성 | 같은 PNG 가 나옴 | 매번 다름 |

가장 아픈 것은 **첫 줄**이다. `burst` 하나를 반경 70·90·100 에 나눠 쓰기 때문에
정수배가 아닌 배율이 반드시 생긴다(vfx-guide §1.2: 이펙트 지름 = 판정 지름).

### 격자 문제 — 시트로 요구하지 않는다

캐릭터 워크 시트는 [`tools/normalize_walk_sheet.gd`](../tools/normalize_walk_sheet.gd) 가
격자를 잡아 주지만, **그 도구는 3열 × 4행 캐릭터 시트 전용이다.** 이펙트는 1행 × N프레임이라
쓸 수 없고, 저장소에 그 모양을 잡아 주는 도구가 없다.

→ **프레임을 한 장씩 따로 뽑는다.** 그러면 격자가 어긋날 일이 없다.
모아서 이어 붙이는 것은 아래 조립 스크립트가 한다(§4-B 마지막).

### 공통 지시문 — 아래 모든 프롬프트 앞에 붙인다

```
게임에 넣을 이펙트 스프라이트 한 장을 만들어 줘.

공통 조건:
- 정사각형 캔버스, 배경은 완전히 투명. 바닥 그림자나 배경색을 넣지 마.
- 이펙트 하나만. 캐릭터, 글자, 프레임, 워터마크, 여러 컷을 넣지 마.
- 색감은 채도가 낮은 흙 톤이야. 형광색·네온·원색을 절대 쓰지 마.
- 부드러운 번짐(글로우, 블러, 그라데이션)을 쓰지 마. 단색 면과 또렷한 가장자리로만.
- 사진처럼 사실적으로 그리지 말고, 2D 게임 이펙트답게 납작하게.
- 이펙트가 캔버스 정중앙에 오고, 상하좌우 여백이 같아야 해.
```

### 프롬프트 — 폭발 (4장, 한 장씩)

세 스킬이 공유한다(반경 70 / 90 / 100 광역). **제자리에서 한 번에 터지고 끝난다** —
이 게임엔 이미 "퍼져 나가며 이동하는 파동"이 따로 있어서 그것과 구분돼야 한다.

```
[1/4] 폭발이 시작되는 순간. 정중앙에 크림색(#F7F3EA) 원이 하나 있고,
그 둘레를 벽돌 붉은색(#C8402F) 링이 감싸고 있어. 링은 가늘고 또렷해.
링 안쪽은 비어 있어(중앙 원 말고는 채우지 마).

[2/4] 같은 폭발의 다음 순간. 중앙의 크림색 원은 절반으로 작아지고,
붉은 링은 더 커지고 두꺼워졌어. 링 바깥으로 삐죽한 삼각형 파편 8개가
45도 간격으로 뻗어 나가. 앞 장과 같은 색, 같은 스타일.

[3/4] 폭발이 끝나가는 순간. 중앙의 원은 사라졌고, 붉은 링은 가장 크지만
아주 가늘어졌고 색이 어두운 적갈색으로 죽었어. 파편 8개는 링에 걸쳐 있어.
링이 캔버스 가장자리에 닿기 직전이어야 해.

[4/4] 폭발의 잔해. 링은 완전히 사라졌고, 작아진 파편 8개만 원형으로
흩어져 남아 있어. 아래쪽 파편 3개는 흐린 회색(#9A9691) 먼지야.
```

### 프롬프트 — 회복 (4장, 한 장씩)

회복 스킬 3종이 공유한다. **아래에서 위로 차오른다** — 이 게임의 다른 연출은 전부
밖으로 퍼지거나 제자리에 머물러서, 위로 가는 움직임이 비어 있다. 그게 식별점이다.

세로로 긴 캔버스가 필요하니 공통 지시문의 "정사각형"을 **"세로로 긴 직사각형(가로:세로 = 2:3)"**
으로 바꾸고, "정중앙" 대신 **"캔버스 아래쪽 1/4 지점이 기준"** 으로 바꾼다.

```
[1/4] 캐릭터 발밑에 놓이는 회복 표시의 시작. 캔버스 아래쪽에
납작하게 눌린 타원 링 하나만 있어. 색은 차분한 올리브 초록(#6F8A46), 가늘고 또렷해.
위쪽은 완전히 비어 있어.

[2/4] 같은 타원 링 위로 짧은 세로선 5개가 솟아오르기 시작했어.
선 색은 앞보다 밝은 연두(#9DBF6E). 선 길이가 서로 제각각이고,
가로 위치도 고르게 배열되지 않고 흩어져 있어. 타원 링은 그대로.

[3/4] 세로선들이 더 위로 올라갔고 중간이 끊겨 점선처럼 됐어.
아래 타원 링은 옅어졌어. 전체적으로 위로 흩어져 올라가는 느낌.

[4/4] 타원 링은 사라졌고, 캔버스 위쪽에 작은 네모 점 4개만 남아 흩어져 있어.
색은 연두(#9DBF6E).
```

> **십자(+) 반짝임을 넣지 말 것.** 다른 연출이 이미 쓰고 있다.

### 프롬프트 — 도발 원 (3장, 한 장씩)

탱커의 즉발 스킬. 반경 260px 원 안의 적이 한 번에 걸린다.
**한 번에 켜졌다 꺼진다** — 퍼지지도 머물지도 않는다. 실제로 순간에 판정이 끝난다.

```
[1/3] 땅에 그려지는 커다란 원형 표시. 정원이고, 선이 굵고 또렷해.
색은 차분한 이끼 초록(#7B9455). 원 안쪽은 완전히 비어 있어(채우면 안 돼).
원이 캔버스를 거의 꽉 채워.

[2/3] 같은 크기의 같은 원인데, 선이 얇아지고 밝은 크림색(#F7F3EA)으로 바뀌었어.
원 위에 안쪽(중심)을 향한 짧은 갈고리 8개가 45도 간격으로 붙어 있어.
갈고리는 초록색이고 45도로 한 번 꺾여 있어 — 안으로 끌어당기는 느낌이야.
**원의 크기는 앞 장과 정확히 같아야 해.**

[3/3] 같은 크기의 같은 원인데, 선이 점선처럼 끊어졌고 색이 어두운 회갈색(#6E6558)으로
죽었어. 갈고리는 없어. **원의 크기는 앞 두 장과 정확히 같아야 해.**
```

> 세 장의 **원 지름이 같아야 한다.** 커지면 파동으로 읽혀서 다른 스킬과 헷갈린다.
> ChatGPT 는 이걸 자주 어기니 뽑은 뒤 겹쳐 보고 확인한다.

### 프롬프트 — 격노 균열 (4장, 한 장씩)

체력 30% 아래에서만 켜지는 탱커의 발악 버프. **주변 공간이 갈라진다** —
감싸는 그림으로 만들면 다른 캐릭터의 자기 강화(감싼다)와 겹친다.

공통 지시문의 "정사각형"을 **"세로로 약간 긴 직사각형(가로:세로 = 3:4)"** 으로 바꾸고,
아래 문장을 **모든 장에 반복해서** 넣는다:

```
캔버스 정중앙의 세로로 긴 영역(전체 폭의 1/4, 높이의 1/3)은 반드시 비워 둬.
거기에 캐릭터가 설 거라 뭔가 그리면 몸을 가려.
```

```
[1/4] 검붉은(#C8402F) 균열 3개가 중앙 빈 영역 바깥에 갈라져 있어.
균열은 45도·수직·수평 직선만 조합해서 꺾여 — 부드러운 곡선을 절대 쓰지 마.
가늘고 짧아.

[2/4] 균열이 5개로 늘고 길어졌어. 각 균열 한가운데에 밝은 크림색(#F7F3EA)
가는 선이 코어처럼 들어 있어. 여전히 45도·수직·수평 직선만.

[3/4] 균열이 7개가 됐고, 가장 긴 것이 캔버스 가장자리에 닿아.
갈라진 틈 사이에 어두운 적갈색이 번져 있어. 크림색 코어는 그대로.

[4/4] 앞 장과 균열 모양은 똑같은데, 크림색 코어만 꺼져서 검붉은 균열만 남았어.
```

### 프롬프트 — 불가침 껍질 (5장, 한 장씩)

쿨타임 45초짜리 3초 무적. 지금 화면에 아무 표시가 없어 플레이어가 걸렸는지조차 모른다.
**한눈에 "지금 못 뚫는다"가 읽혀야 한다.** 움직임은 **굳는다** — 조각이 모여 딱 멈춘다.

격노 균열과 같은 캔버스 비율과 "중앙을 비워 둬" 문장을 쓴다.

```
[1/5] 흐린 청회색(#6B8FA8) 정육각형 판 6개가 캔버스 바깥쪽에 흩어져 있어.
각 육각형은 테두리만 있고 속은 비어 있어. 테두리는 가늘어.

[2/5] 같은 육각형 판 6개가 중심 쪽으로 절반쯤 모여들었어. 아직 서로 닿지 않았어.

[3/5] 육각형 판들이 서로 맞물려 중앙을 둘러싼 하나의 큰 육각형 껍질이 완성됐어.
껍질 테두리는 **눈에 띄게 두꺼워**. 속은 비어 있어(뒤가 보여야 해).
판이 맞물린 이음새 6곳에 작은 크림색(#F7F3EA) 점이 박혀 있어.

[4/5] 앞 장과 같은 껍질인데 이음새의 크림색 점이 없어졌어.
아래쪽 판 3개의 테두리는 더 어두운 청회색이야.

[5/5] 앞 장과 똑같은데 이음새의 크림색 점이 다시 켜졌어.
```

> **껍질 테두리를 두껍게** 하는 것이 이 연출의 요점이다. 얇으면 기존 상태 링과 구분이 안 된다.

### 뽑은 뒤 — 프레임을 이어 붙인다

낱장이 모이면 균일 격자 시트로 조립한다. `tools/` 에 조립 스크립트를 하나 두고:

1. 각 장을 **알파 경계상자 기준으로 캔버스 정중앙에 재배치**한다.
   ChatGPT 는 여백을 장마다 다르게 주므로 이 단계가 없으면 재생할 때 이펙트가 떨린다.
   (격노 균열·불가침 껍질처럼 중앙이 비는 것은 경계상자 중심이 곧 캐릭터 자리라 그대로 맞는다.)
2. 모든 장을 **같은 프레임 크기**로 맞춘다. 가장 큰 장에 맞춰 나머지에 투명 여백을 준다.
3. 가로로 이어 붙여 1행 × N프레임 시트로 저장한다.
4. `.import` 파일까지 함께 커밋한다.

**알파는 건드리지 않는다.** 반투명 가장자리에 색을 스냅하면 외곽에 테두리가 생긴다 —
초상 작업에서 실제로 겪은 문제다.

### 확인 항목

| | 확인 |
|---|---|
| 크기 일관성 | 도발 원 3장의 **지름이 같은가**(겹쳐 보고 확인) |
| 크기 일관성 | 폭발 4장에서 링이 단조 증가하는가 |
| 빈 영역 | 격노 균열·불가침 껍질의 **중앙이 비었는가** |
| 대칭 | 폭발이 방사 대칭인가(반경에 맞춰 스케일되므로 한쪽으로 쏠리면 안 된다) |
| 알파 | 배경이 진짜 투명인가(흰 배경을 투명처럼 그려 주는 경우가 있다) |
| 곡선 | 격노 균열에 곡선이 섞이지 않았는가 |

## 5. 산출물이 오면 — 붙이는 순서

**아트만으로는 아무것도 화면에 안 나온다.** 각 항목에 코드 한 자리가 따라붙는다(§3-A 표).

`tools/gen_effects.py` 는 **저장소에 커밋한다.** 산출물 PNG 만 두면 나중에 굵기 하나를 고치려고
처음부터 다시 그려야 한다 — `gen_icons.py` 를 남겨 둔 것과 같은 이유다.
PNG 와 함께 `.import` 파일도 커밋한다(안 하면 `ResourceLoader.exists()` 가 false 다).

붙이는 순서는 **값싸고 효과 큰 것부터** — vfx-guide §4 "2단계"와 같은 원칙이다.

1. **회복 숫자** — `DamageNumberSpawner` 에 `healing_applied` 분기. 아트 없이도 즉시 효과가 크다.
2. **회복 연출** — 위 리스너에 프롬프트 A-2 를 얹는다. 스킬 3개가 한 번에 채워진다.
3. **폭발** — `Projectile._explode()` 한 자리. 스킬 3개가 한 번에 채워진다.
4. **강지 E 껍질** — 공백 중 가장 나쁜 자리(45초 쿨 무적이 안 보인다).
5. **하랑 Q 원 → E 균열** — 연출이 하나도 없는 유일한 캐릭터를 채운다.
6. **StatusRing 을 버프까지 확장**(§3-B) — 설아 E·강지 지대가 함께 해결된다.

> 3 번을 4 번보다 앞에 두는 이유: 한 자리를 고치면 세 스킬이 채워지는데, 강지 E 는 한 자리에 하나다.
> 다만 **개별 심각도는 강지 E 가 가장 크다** — 급하면 순서를 바꿔도 된다.

각 항목마다 별도 이슈로 쪼갠다. 이 문서는 정리와 프롬프트까지다.
