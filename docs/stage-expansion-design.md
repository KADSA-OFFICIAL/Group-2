# 스테이지 확장 설계 — 남은 5스테이지(2-2~3-3)

> 이 문서는 GitHub 이슈 [#564](https://github.com/KADSA-OFFICIAL/Group-2/issues/564) 본문(2026-10-08)을 **그대로** 옮긴 설계 정본이다(#565). 아래 첫 인용문의 "이 이슈"는 #564 를 가리킨다. 구현은 하위 이슈(#563 · #565 · #566 · #567, 후속 #568)에서 하고, 설계가 바뀌면 이 문서와 이슈를 함께 고친다.

---

> **이 이슈가 설계 정본이다.** 구현은 하위 이슈 단위로 한다 (이슈 하나 = 브랜치 하나 = PR 하나). #565 의 PR 에서 이 본문을 `docs/stage-expansion-design.md` 로 커밋한다.

## Summary

3챕터 × 3스테이지 구조(#408)에서 비어 있는 **2-2 · 2-3 · 3-1 · 3-2 · 3-3** 을 저작해 9스테이지를 완성한다.
새 적을 만들지 않고 **기존 6종을 재사용**하며, 뒤 챕터의 난이도는 **스테이지별 적 레벨 보정**으로 올린다. 보상은 **챕터가 장비 티어를 여는** 구조로 짠다. 바다·하늘 테마 적은 아트가 준비되면 후속 이슈에서 교체한다.

### 합의된 결정

| 항목 | 결정 |
|---|---|
| 범위 | 남은 5개 전부 (2-2, 2-3, 3-1, 3-2, 3-3) |
| 적 | 기존 6종 재사용으로 먼저 연다. 수룡·익룡 테마 적은 후속(#568)에서 교체 |
| 난이도 | `StageData` 에 스테이지별 적 레벨 보정 필드 (턴제 전용) |
| 보상 | 챕터가 장비 티어를 연다 (2챕터 = 철, 3챕터 = 후다만티움) |

## Motivation or Problem

- 9스테이지 중 4개(1-1, 1-2, 1-3, 2-1)만 저작되어 있다. 2챕터는 1/3, 3챕터는 0/3 이다. 하늘 전장 맵(#423)·하늘 전투 배경·하늘 전투곡·최종 보스곡(#537, #539)은 이미 준비되어 있는데 쓰는 스테이지가 없다.
- 스토리 3장(바다), 5장(하늘·여왕전)의 전투에 대응하는 스테이지가 없다.
- **적 레벨이 적 정의(`EnemyData.turn_level`)마다 고정**이라, 같은 적을 다시 쓰면 3챕터도 1챕터와 같은 강도다.
- **장비 재료의 출처가 게임 안에 없다.** 스테이지 보상은 gold·protein·stone 뿐이고 상점은 비어 있다(`data/shop` 에 항목 없음). 그래서 주석·구리·철광석·석탄·후다만티움이 들어올 길이 없어, 돌 갑옷(석탄 2)·철·후다만티움 장비를 일반 플레이로는 만들 수 없다.

## Current Behavior

- `StageDatabase.get_authored_chapters() == [1, 2]`. 출격 화면에 2챕터는 2-1 하나뿐이고 3챕터 장은 없다.
- 턴제 전투의 적 레벨은 `EnemyData.turn_level`(랩터 20 · 매머드/서아 22 · 보스 25) 그대로다. 아군 레벨은 1파 적의 최고 레벨에 맞춰진다(`TurnBattleManager.start()`, 설계서 §12 "파티 레벨").
- 삼각근 Lv. 성장이 전투에 들어가지 않는다 (#563). 지금 플레이어가 전투에서 실제로 강해지는 길은 장비뿐이다.

## Expected Behavior

### 1. 스테이지 구성 (재사용 버전)

모두 `type = BATTLE`(소탕), `spawns` 는 비우고 **웨이브만** 쓴다(README "섞지 않는 편이 낫다"). 웨이브당 적은 5체 이하(적 랭크 5개).

| 스테이지 | 이름 | 웨이브 (라벨 — 적) | 적 레벨 보정 | 적 Lv. | 의도 |
|---|---|---|---|---|---|
| 2-2 | 갯바위 길목 | 1파 「길목의 척후」 랩터 ×2 · 랩터2 · 서아<br>2파 「행렬을 끊는 무리」 매머드 ×2 · 서아 | **+3** | 23 / 25 | 서아(후열 원거리)를 처음부터 섞어 후열 처리를 묻는다 |
| 2-3 | 물가의 주인 **(보스)** | 1파 「물가를 지키는 무리」 매머드 · 서아 · 랩터 · 랩터2<br>2파 「우두머리」 매머드 수인 우두머리 단독 (`is_boss`) | **+5** | 25·27 / 보스 30 | 2챕터의 벽. 한기·화염 약점 → 설아·미나. 힐러 점검(1-3 과 같은 성질) |

| 3-2 | 여왕의 성문 | 1파 「성문 앞 초병」 랩터 · 랩터2 · 서아<br>2파 「문지기」 매머드 · 랩터2 ×2<br>3파 「성문 수비대」 서아 · 매머드 · 랩터 · 랩터2 | **+7** | 27 / 29 | 3연속 소모전. 힐러 없는 파티를 압박한다 |

(랩터 = 벨로시랩터 수인, 랩터2 = 벨로시랩터 수인 2, 매머드 = 매머드 수인)

**지켜야 할 규칙**

- **하늘 챕터의 BOSS 등급은 3-3 2파에만 둔다.** `TurnBattle._boss_music()` 이 하늘 컨셉의 보스 웨이브에 최종 보스곡(Last Sanctuary)을 건다. 3-1·3-2 에 보스를 넣으면 최종곡이 미리 나온다.
- **점령 타입을 쓰지 않는다.** 턴제에는 점령 대응물이 없어(설계서 §18) 점령 스테이지는 턴제에서 원래 의도보다 쉬워진다.
- **새 챕터의 첫 스테이지는 앞 챕터 보스보다 쉽고 덜 준다** (2-1 < 1-3, 3-1 < 2-3). 2-1 설명에 적힌 원칙을 그대로 따른다.

**플레이어용 브리핑(`briefing`, 초안)**

- 2-2: 마을 사람들을 이끌고 해안을 따라가는 길, 갯바위 틈 길목에서 수인 무리가 행렬을 막아선다. 앞을 뚫으면 뒤를 끊으러 매머드 수인들이 몰려온다. 뒤에서 쏘아 대는 서아를 먼저 노리자.
- 2-3: 드디어 찾아낸 물가. 그런데 이미 그곳에 터를 잡은 무리가 당장 꺼지라며 막아선다. 지키는 무리를 물리치면 우두머리가 직접 나선다.
- 3-1: 납치된 소꿉친구를 구하러 하늘섬으로 향하는 구출대. 구름 위 바위 다리에서 여왕이 보낸 추격대가 길을 막는다. 재빠른 랩터 수인부터 흩어 놓자.
- 3-2: 여왕의 성으로 들어가는 마지막 관문. 문지기들이 세 차례에 걸쳐 몰려온다. 숨 돌릴 틈 없는 소모전이니 회복을 아끼지 말자.
- 3-3: 허락 없이 성에 들어선 구출대를 여왕의 근위대가 맞는다. 근위대가 무너지면 여왕이 직접 날아든다. 친구를 되찾아라!

2-3 브리핑은 종족 이름을 쓰지 않는다 — 지금은 매머드 수인 우두머리가 임시로 서고, 스토리상 상대인 수룡은 #568 에서 들어온다.

### 2. 난이도 — 스테이지별 적 레벨 보정 (#565)

```
턴제 적 레벨 = EnemyData.turn_level + StageData.turn_level_bonus   (기본 0)
```

- 적 정의를 복제하지 않고 스테이지가 강도를 정한다. 기존 스테이지는 0 이라 그대로다.
- 레벨이 오르면 적 기준 곡선(`TurnCombatTuning.enemy_base_*`)이 그대로 적용된다: Lv20 → Lv30 이면 HP ×2.4 · 공격 ×1.9 · 방어 ×1.6.
- 아군 레벨(파티 레벨)은 지금처럼 **1파 최고 레벨**이며 보정이 포함된다. 보스 웨이브에서 아군이 보스보다 3 낮은 것은 1-3 과 같은 기존 동작이고 유지한다.
- **실시간 전투에는 적용하지 않는다** (실시간에는 레벨 개념이 없다).

### 3. 보상 — 챕터가 장비 티어를 연다 (#566 · #567)

모두 `[임시값]`. 결과 화면 칩 수를 생각해 **스테이지당 재화 5종 이하**로 둔다.

|---|---|---|---|---|---|---|---|---|
| 1-3 (수정) | 180 | 200 | 110 | | **+2** | | | |
| 2-1 (수정) | 110 | 120 | 70 | **+4** | **+1** | | | |
| 2-2 | 160 | 160 | | 6 | 2 | 6 | | |
| 2-3 | 280 | 280 | | 10 | 4 | | 6 | |
| 3-1 | 240 | 240 | | 3 | 3 | | | 4 |
| 3-2 | 320 | 320 | | 4 | 4 | | | 6 |
| 3-3 | 480 | 480 | | 6 | 6 | | | 10 |

**목표: 챕터 첫 클리어 + 반복 3~4회 ≈ 다음 티어 장비 한 벌** (무기 · 투구 · 갑옷 · 각반 4부위)

| 티어 | 필요 재료 | 공급 |
|---|---|---|
| 돌 | stone 36 · coal 2 · gold 440 | 1챕터 첫 클리어(stone 190 · gold 310 · coal 2) + 1-3 1회 반복 |
| 철 | iron_ore 36 · coal 14 · gold 1040 | 2챕터 첫 클리어(ore 20 · coal 7 · gold 550) + 2-3 ×2 + 2-2 ×1 → ore 46 · coal 17 · gold 1270 |
| 후다만티움 | hudamantium 27 · coal 23 · gold 2260 | 3챕터 첫 클리어(huda 20 · coal 13 · gold 1040) + 3-2 ×2 + 3-1 ×2 → huda 40 · coal 27 · gold 2160 (+2챕터 잔액) |

- 청동 거울(tin 6 · copper 6)은 2-2 · 2-3 첫 클리어로 맞춰진다. 거울은 여신 스킬 강화(실시간 전용)라 턴제 전력과는 무관하다.
- 프로틴 첫 클리어 누적 → 삼각근 Lv.: 2-1 후 470 (Lv.5) → 2-3 후 910 (Lv.6) → 3-3 후 1950 (Lv.8). 2챕터 반복분을 더하면 3챕터 진입 때 Lv.7~8 이다 → 아래 실측 프로필 P1 · P2 의 근거.
- **가정: 장비 1개를 여러 캐릭터가 동시에 착용할 수 있다** (`EquipmentSystem.equip()` 이 다른 캐릭터의 착용을 확인하지 않는다). 그래서 "티어당 한 벌"을 목표로 잡았다. 1인 1개로 막게 되면 재료 목표를 파티 인원만큼 늘려야 한다.

### 5. 실시간 전투와의 관계

- 새 스테이지는 실시간(`main_realtime.tscn`)에서도 **열리고 끝까지 진행 가능**해야 한다. 밸런스는 턴제 기준이다.
- 스폰 좌표는 각 맵의 걸을 수 있는 자리여야 한다. 특히 하늘 맵은 섬 밖이 허공 충돌이다 → #566 · #567 에 권장 좌표가 있다.

## Player Flow

1. 1챕터를 마친 플레이어가 출격 화면에서 2챕터 장으로 넘긴다 → 2-2 「갯바위 길목」 타일에 NEW 가 붙어 있다.
2. 2-2 를 깨면 결과 화면에 철광석·석탄·주석 칩이 뜬다 → 제작 화면에서 철 장비 재료가 차기 시작한다.
3. 2-3 우두머리에서 막히면 2-1 · 2-2 를 반복해 철 장비와 삼각근 Lv.을 올린 뒤 다시 도전한다.
4. 2-3 을 깨면 3챕터(하늘) 장이 열린다 (해금 규칙은 #434). 3-1 「구름 다리」.
5. 3-1 · 3-2 로 후다만티움을 모아 장비를 갖춘 뒤 3-3 여왕전에 들어간다. 2파에서 최종 보스곡이 나온다.
6. 3-3 을 깨면 9스테이지를 완주한다.

## Non-goals

- **신규 테마 적** — #568. 이번엔 기존 6종만 쓴다. 그래서 하늘 챕터에 육지 수인이 나온다 (잔여 위험).
- **여신 최종전 (스토리 6장)** — 3×3(#408) 밖이고 여신 적 정의도 없다.
- **해금 사슬 · 챕터 잠금** — #434 / #541 범위. 함께 진행하는 것을 권한다.
- **스토리 BATTLE 줄 → 출격 연결** — #541 범위. 대응표만 남긴다.
- **실시간 밸런스** — 레벨 보정은 턴제 전용이다. 실시간은 "열리고 진행 가능"만 보장한다.
- **적 레벨 UI 표시**, **웨이브별 · 스폰별 보정**, **스테이지가 정하는 사이클 제한** — 쓰임새가 생기면 그때 만든다. 실측에서 교착은 없었다(평균 ≤ 27사이클).
- **1챕터 재조정** — #563 수정 뒤 1챕터가 쉬워지는 것은 받아들인다(입문 챕터).
- **캐릭터 레벨 시스템** — 설계서 Phase 2, 별도.

## UX / Balance expectations — 실측 근거

엔진의 자동 전투로 실제로 쟀다. 임시 스크립트로 재었고(저장소 밖), 보정은 `EnemyData` 사본의 `turn_level` 을, 성장은 사본 캐릭터의 기초 스텟을 올려 흉내 냈다. #563 을 고친 뒤의 성장과 같은 값이다.
조건: 표준 파티 **미나 · 하랑 · 설아 · 강지**, 시드 8개, 사이클 제한 60, 실제 전투처럼 `use_prep("energy")`.

**전력 프로필**
