**있다 — 초상.** 사용자 지급 일러스트(은발·보라 드레스·금 장식·지팡이)가 캐릭터 디자인의 정본이다.

## 1. 기본 규격

| 항목 | 값 | 근거 |
|---|---|---|
| 셀 | **48 × 48 px** | 아린과 같은 격자 |
| 캐릭터 키(셀 안) | **36 px** | |
| 셀 안 발 기준선 | **y = 44** (아래 여백 3px) | |
| 시트 | **144 × 192** (3열 × 4행) | 4방향 × 3프레임 |
| `walk_sprite_scale` | **(4, 4)** | 아래 계산 |
| `walk_sprite_offset` | **(0, -15)** | 아래 계산 |
| 화면 키 | **144 px** | 파티 108px 의 1.33배 |
| 아웃라인 | 1px, 셀렉티브 | |
| 디더링 | 드레스 자락의 성운 표현에만 | |

### 왜 배율 4 인가 — 정수 오프셋이 배율을 정한다

`walk_sprite_offset` 은 발을 충돌 캡슐 바닥에 맞추는 값이고, 계산식은
[enemies/README.md](../assets/sprites/enemies/README.md) 와 같다:

```
offset.y = F / scale - (발 기준선 - 셀 높이/2)
```

여왕의 캡슐 높이는 40 이므로 바닥은 원점에서 `F = 20` 이다.
**`F / scale` 이 정수여야 오프셋이 정수가 된다**(서브픽셀 금지). 20 의 약수만 후보다:

| 배율 | `20 / scale` | 화면 키 | 판정 |
|---|---|---|---|
| 2 | 10 ✓ | 72 px | ✗ 파티(108)보다 **작다**. 보스가 파티보다 작으면 안 된다 |
| **4** | **5 ✓** | **144 px** | ✓ 파티의 1.33배 — 보스로 읽히면서 화면을 덮지 않는다 |
| 5 | 4 ✓ | 180 px | 파티의 1.67배. 더 압도적으로 갈 거면 이쪽 (§5 결정 항목) |

배율 3 은 `20 / 3 = 6.67` 이라 **탈락**한다. 아린이 배율 3 인 것과 다른 이유가 여기 있다 —
아린은 파티 캡슐(높이 30)이라 `F = 15` 였고 3 으로 나누어떨어졌다.

배율 4 로 확정하면:

```
offset.y = 20 / 4 - (44 - 24) = 5 - 20 = -15
```

우연히 아린과 같은 `-15` 가 된다. 셀 격자와 발 기준선을 같게 잡았기 때문이다.

### 다른 적과의 크기 관계

기존 적은 큰 생성기 시트를 `walk_sprite_scale 0.25` 로 줄여 **화면 키 약 119px** 이다
(매머드·벨로시랩터·돌창병). 여왕 144px 은 그보다 **한 뼘 크다** — 잡졸 사이에 서면
실루엣만으로 보스가 구분된다.

### 텍스처 필터

`project.godot` 에 `default_texture_filter` 가 없어 프로젝트 기본값은 **Linear** 다.
**여왕의 `AnimatedSprite2D` 노드에서만** `texture_filter = Nearest` 로 덮는다.
전역 설정을 바꾸면 0.25 로 줄여 쓰는 기존 적 시트가 거칠어진다.
빼먹으면 4배 확대한 도트가 뭉개진다 — **작업 시작 전 첫 확인 항목**이다.

**16색.** 눈과 드레스가 램프를 공유한다.

### 2.1 ⚠ `tint` 가 `LILAC` 과 거의 같다 — 결정이 필요하다

`pterosaur_queen.tres` `tint = Color(0.66, 0.55, 0.8)` = **`A88CCC`**.
`UITheme.LILAC` 은 **`A78BC8`** — 눈으로 구분되지 않는다.

이게 왜 문제인가: [`EnemyBase`](../entities/enemies/EnemyBase.gd) 가 발사할 때
`data.tint` 를 탄 색으로 실어 보낸다(`Projectile` 생성 인자). 그런데 vfx-guide §1.4 는
`LILAC` 을 **"상태 이상(디버프) 표시"** 로 예약해 두었다.
→ **날아오는 탄과 발밑 디버프 링이 같은 색이 된다.** 게다가 여왕은 4타마다 실제로
`stun` 을 걸기 때문에, 탄과 그 결과가 화면에서 겹친다.

→ **`tint` 를 `8B6BB0` 으로 한 단계 어둡게 하는 것을 제안한다.** 일러스트의 보라 정체성을
유지하면서 `LILAC` 디버프 링이 그 위에 떠도 갈린다. 데이터 변경이라 이 문서가 바꾸지 않는다 — §5.

`tint` 는 **실제 아트에 곱해지지 않는다**(`EnemyBase._apply_data()` 주석). 워크 시트가 붙는
순간부터 `tint` 는 오직 **탄 색**으로만 쓰인다.

## 3. 캐릭터 스프라이트

### 실루엣 설계

36px 에서 판독되어야 하고, **잡졸(벨로시랩터·매머드)과 한 화면에 있을 때 즉시 갈려야 한다.**
식별 요소 3가지:

1. **비대칭 스파이크 헤드피스** — 실루엣 상단 오른쪽으로 솟은 2~3개 뿔
2. **바닥까지 끌리는 드레스 자락** — 실루엣 **하단이 넓게 퍼진다**.
   네 발로 웅크린 랩터·덩치로 넓은 매머드와 달리 **위는 좁고 아래가 퍼지는 삼각형**이다
3. **오른손의 긴 지팡이** — 실루엣을 세로로 가르는 직선 + 상단 초승달 고리.
   **로스터·적 통틀어 세로 직선을 가진 유일한 유닛이다**

머리 위 여백 8px(y 0~7)이 헤드피스 자리다.

### 얼굴 (36px 키 기준)

아린 문서 §3 과 같은 예산이다 — **눈·눈썹·입 세 개만** 넣고 코·귀·볼은 버린다.

- 눈: 세로 3px, 가로 4px. 홍채 `8B6BB0`, 하이라이트 1px `CREAM`
- 눈썹: 1px. **바깥쪽 끝을 1px 올려** 내려다보는 인상 — 아린(안쪽 끝 1px 내림 = 호전적)과 갈린다
- 입: 1~2px 옅은 호. 웃음기만 남기고 이는 그리지 않는다

> 아린이 "도발적"이라면 여왕은 **"내려다본다"** 다. 도트에서 이 차이는 눈썹 방향 하나로 난다.

### 애니메이션 — 워크 4방향뿐이다

| 이름 | 프레임 | FPS | 루프 |
|---|---|---|---|
| `walk_down` / `walk_left` / `walk_up` / `walk_right` | 각 3 | 8 | O |

**총 12장.** 행 순서(하/좌/상/우)와 **0번 = 정지 포즈**는
[`WalkAnimation`](../entities/shared/WalkAnimation.gd) 이 정한 것이라 바꿀 수 없다.

### 워크 3프레임의 짜임

**발이 거의 보이지 않는 캐릭터다** — 드레스 자락이 발목을 덮는다.
그래서 보행은 **다리가 아니라 자락과 머리카락으로** 읽혀야 한다.

| 프레임 | 자세 |
|---|---|
| 0 | **정지 포즈** — 무게 중심 중앙, 지팡이 수직, 자락 정지 |
| 1 | 몸통 −1px(살짝 뜸), 자락 왼쪽으로 2px, 머리카락 끝 1px 뒤로 |
| 2 | 몸통 −1px, 자락 오른쪽으로 2px, 머리카락 끝 1px 앞으로 |

- 몸통을 **위로** 1px 띄운다(아린은 아래로 눌렀다). 미끄러지듯 걷는 인상이 난다
- 자락·머리카락은 몸통보다 **1프레임 늦게** 따라온다
- **지팡이는 흔들지 않는다.** 세로 직선이 식별 요소인데 흔들면 무너진다
- `walk_left` 를 좌우 반전해 `walk_right` 로 쓰지 않는다 — 지팡이가 반대손으로 넘어간다

## 4. 이펙트

여왕이 화면에 만드는 사건은 **두 가지뿐**이다. 나머지는 이미 공용 노드가 처리한다
(피해 숫자 `DamageNumberSpawner`, 피격 플래시 `HitFlash`, 상태 이상 링 `StatusRing`).

### 4.1 평타 탄 (일반)

| 값 | 수치 | 출처 |
|---|---|---|
| 속도 | 340 px/s | `projectile_speed` |
| 명중 반경 | **16** px | `projectile_hit_radius` |
| 색 | `data.tint` | `EnemyBase` → `Projectile` |

vfx-guide §1.2 **[확정]** — 이펙트 지름 = 판정 지름. 배율 4 이므로 반경 16 은 **정확히 4도트**다.
격자에 떨어진다(아린 착탄 반경 55 가 18.33 도트로 어긋났던 것과 대조적이다).

- 8×8 도트 스프라이트. 코어 2×2 `CREAM`, 그 둘레 4도트 반경까지 드레스 메인색
- 3프레임 루프로 **깜빡이는 게 아니라 회전**한다(4갈래 별의 각도를 15°씩 — 사전 렌더 3장)
- 꼬리 3도트, 알파 60/40/20%

### 4.2 강화탄 (4타째)

**같은 그림을 키우기만 하면 안 된다.** 이 탄은 ×1.5 피해에 **기절**을 싣는다 —
맞으면 이동·공격·스킬이 전부 막히므로, **날아오는 동안 피할 수 있어야** 공정하다.

| 요소 | 일반탄 | 강화탄 |
|---|---|---|
| 크기 | 8×8 | **12×12** |
| 코어 | 2×2 `CREAM` | 4×4 `AMBER` (금색) |
| 갈래 | 4갈래 별 | **6갈래 + 바깥 링 1px** |
| 꼬리 | 3도트 | **6도트, 지그재그** |

**색을 금(`AMBER`)으로 바꾸는 것이 핵심이다.** 크기 차이는 난전에서 안 보이지만 색은 보인다.

> **판정 반경은 그대로 16 이다.** 강화탄만 크게 그리는 것은 vfx-guide §1.2(이펙트 지름 =
> 판정 지름)에 어긋나 보이지만, 여기서는 **의도된 예외**다 — 판정을 키우지 않고 "위험하다"만
> 알린다. 그림이 판정보다 크면 스치고도 안 맞는 일이 생기는데, 그 오차가 유리한 방향
> (플레이어가 안 맞음)이라 받아들인다. 반대(그림이 작음)였으면 안 된다.

### 4.3 만들지 않는 것

- **발사 예고**: 코드 경로가 없다(§0). 있으면 강화탄 회피가 훨씬 읽힌다 — §5 결정 항목
- **기절 표시**: `stun` 은 이미 [`StatusRing`](../entities/combat/StatusRing.tscn) 이 그린다.
  아린의 `shock_stun` 이 전용 노드(`ShockStatusEffect`)를 쓰는 것과 다르다
- **사망 연출**: 재생 코드 없음

## 5. 결정이 필요한 것 (임의로 정하지 않았다)

| # | 항목 | 제안 | 이유 |
|---|---|---|---|
| 1 | `tint` = `A88CCC` | `8B6BB0` 로 변경 | `UITheme.LILAC`(`A78BC8`, 디버프 예약색)과 구분되지 않는다 (§2.1) |
| 2 | 화면 키 144 vs 180 | **144**(배율 4) | 180 은 압도적이지만 잡졸 2마리와 함께 나오는 웨이브에서 화면을 덮는다 |
| 3 | 원거리 평타 발사 예고 | 별 이슈로 추가 | 없으면 강화탄 기절을 **볼 수는 있어도 준비할 수 없다** (§4.3) |
| 4 | 초상 도입 | 사용자 지급 일러스트 사용 | `EnemyData.portrait` 가 비어 있다. 누끼·정규화 필요 |

1·3·4 는 데이터·코드 변경이라 **별도 이슈**다. 이 문서는 스펙만 갖는다.

## 6. 작업 순서

1. **§5 의 1번(tint) 을 먼저 정한다** — 탄 색이 여기서 나온다
2. **텍스처 필터 확인** — `AnimatedSprite2D.texture_filter = Nearest`
3. **`walk_down` 0번 프레임** — 실루엣·얼굴 확정. **이 게임의 Idle 이 이 한 장이다**
4. `walk_down` 3프레임 → `walk_left` 3프레임 → `walk_up` / `walk_right`(반전 금지)
