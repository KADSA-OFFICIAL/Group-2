# 턴제 전투 정지 스프라이트 프롬프트 (#478)

턴제 전투 화면에서 **네모로 서 있는 것들**을 그림으로 바꾸기 위한 프롬프트 모음.

각 프롬프트는 **자기 완결적**이다 — 생성 도구는 이 저장소를 읽지 못하므로 필요한
규약·수치를 프롬프트 안에 전부 적었다. 값이 바뀌면 프롬프트가 아니라 아래 정본을 본다.

| 대상 | 정본 |
|---|---|
| 표시 칸·발 기준선 | `stage/turn/TurnBattle.gd` 의 `ALLY_BODY` / `ENEMY_BODY` |
| 원소 7색 · UI 색 | `entities/combat/turn/TurnCombat.gd` |
| 공통 아트 규율 | 캐릭터 아트 에셋 제작 가이드 §5 |
| 초상·컷인·엠블럼 | [turn-combat-design.md](turn-combat-design.md) §14 "캐릭터 아트 적용" |
| 워크 시트(실시간 화면) | [pixel-art-prompts.md](pixel-art-prompts.md) — **이 문서와 다른 에셋이다** |

---

## 0. 네모의 정체

턴제 전투 화면은 Phase 0(감각 검증) 단계라 유닛을 `ColorRect` 로 세운다.
`tint` 색 네모 하나가 캐릭터 자리를 대신하고, 그 위에 원소 문양 라벨만 붙는다.

지금은 `battle_sprite` 슬롯이 열려 있다.

```
CharacterData.battle_sprite : Texture2D   # 아군
EnemyData.battle_sprite     : Texture2D   # 적
```

**비어 있으면 네모, 채우면 그림이다.** `.tres` 에 텍스처만 넣으면 되고 스크립트를
고칠 필요가 없다. 아래 프롬프트의 산출물이 곧 이 슬롯에 들어간다.

### 워크 시트를 빌려 쓰지 않는 이유

`assets/sprites/characters/` 에 이미 워크 시트가 있고 그 한 컷을 잘라 쓸 수도 있다.
그러면 오늘 당장 네모가 사라진다. 다만 워크 시트는 **실시간 화면의 4방향 이동용**이라
측면 컷이 "걷다 멈춘 자세"로 굳어 보이고, 셀 안 인물이 프레임마다 흘러가는 문제
(`tools/normalize_walk_sheet.gd` 머리말)를 이 화면에서 다시 겪는다.
급하면 임시로 쓸 수 있지만, 이 문서가 요구하는 것은 **제자리 전투 자세 한 장**이다.

## 1. 어느 도구에 무엇을 시키나

| 산출물 | 도구 | 왜 |
|---|---|---|
| **네모 대체 플레이스홀더** | **Codex** (Pillow 스크립트) | 실루엣·무기 도형·팔레트만 있으면 코드로 그려진다. 12체를 한 번에 뽑고, 값을 바꿔 다시 뽑을 수 있다 |
| **최종 전투 스프라이트** | **이미지 생성** (ChatGPT 등) | 얼굴이 있는 인물은 Pillow 도형으로 못 그린다 |

> `pixel-art-prompts.md` 가 이미 같은 결론을 적어 두었다: *"얼굴이 있는 치비 스프라이트는
> Pillow 도형으로 못 그린다."* **Codex 레인은 최종 아트가 아니라 "네모보다 나은
> 플레이스홀더"다.** 이걸 최종본으로 착각하지 말 것.
>
> 그래도 Codex 레인이 값을 하는 이유: 지금 화면에서 네 캐릭터가 **색만 다른 똑같은
> 네모**라 누가 탱커고 누가 딜러인지 전장에서 구분되지 않는다. 실루엣과 무기 도형만
> 들어가도 그 문제가 사라진다.

## 2. 공통 규격 — 두 레인 모두 지킨다

### 2-1. 표시 칸과 발 기준선

```
아군 칸  56 × 84 px      적 칸  62 × 78 px
발밑이 노드 원점이다 (position = -칸 * (0.5, 1))
```

전투 화면은 `STRETCH_KEEP_ASPECT_CENTERED` 로 넣으므로 **늘어나지 않는다.**
대신 비율이 다르면 칸 안에 여백이 생긴다. 아래 캔버스 비율을 맞추면 여백이 없다.

| 대상 | 제작 캔버스 | 배율 | 화면 크기 |
|---|---|---|---|
| 아군 | **224 × 336** | 1/4 | 56 × 84 |
| 적 | **248 × 312** | 1/4 | 62 × 78 |

4배로 그리는 이유: 나중에 표시 칸이 커져도 다시 그리지 않는다(§2-4).

### 2-2. 등신 — 여기서는 치비다

캐릭터 아트 가이드 §5 는 **7~7.5등신**을 고정으로 못박는다. 그건 전신 일러스트·컷인
기준이고, **이 에셋에는 적용할 수 없다.**

```
화면 표시 높이 84px 에서 7등신 → 머리 12px → 눈·입이 1px 씩 → 얼굴이 사라진다
```

이 에셋은 **4등신**으로 그린다(머리 = 전체의 1/4 ≈ 화면 21px). 가이드와 어긋나는
지점이므로 적어 둔다 — 어긋난 게 아니라 **다른 용도**다. 컷인·편성 전신은 계속
7~7.5등신을 지킨다.

### 2-3. 그 외 공통 규율 (가이드 §5 그대로)

| 항목 | 값 |
|---|---|
| 광원 방향 | **좌상단 45° 고정** |
| 그림자 색 | **순수 검정 금지.** 주색의 보색 계열 어두운 톤 |
| 팔레트 상한 | 캐릭터당 주색 2 + 보조 1 + 강조 1 = **4색 이내** |
| 원소 색 | 의상 어딘가에 자기 원소 색을 **반드시** 포인트로 넣는다 |
| 채도 | 배경(`#0C111C` 배경 / `#141C2C` 바닥)과 충돌하지 않게 과채도 금지 |
| 배경 | **완전 투명 PNG.** 접지 그림자는 화면이 따로 그린다 — 그림에 넣지 않는다 |
| 방향 | **오른쪽을 보는 측면 3/4.** 아군은 우측(적 쪽)을 본다. 적은 좌우 반전해서 쓰지 않고 **왼쪽을 보게** 그린다 |
| 자세 | 제자리 전투 대기. 무기를 들고 무게중심을 약간 낮춘다. 걷는 중간 자세 금지 |
| 여백 | 캔버스 좌우에 각 5%, 위에 5%. **발끝은 캔버스 밑변에 붙인다** (발 기준선이 밑변이다) |

### 2-4. 표시 칸을 키울지는 아직 정하지 않았다

가이드 §2.3 은 1080p 에서 캐릭터 표시 높이를 **340~400px** 로 잡는다.
이 화면 기준(720p)으로 환산하면 227~267px 인데, 지금 칸은 **84px** 다. 3배 차이다.

칸을 키우면 얼굴이 살아나지만 **전장 구도가 전부 흔들린다** — 적 클러스터 높이
(`CLUSTER_GAP`), 조준 프레임(58×54), 적 간격(112px), 아군 줄 간격(84px)이 모두
지금 칸 크기에 맞춰져 있다. 아트 이슈에서 임의로 정하지 않는다.

**지금은 84px 을 전제로 4등신으로 그린다.** 캔버스를 4배로 두는 이유가 이것이다 —
칸을 키우기로 결정해도 같은 파일을 그대로 쓴다.

## 3. 대상 목록 — 12체

원소색은 `TurnCombat.ELEMENT_COLOR` 값이다. `tint` 는 지금 네모를 칠하는 색이고
**디버그용 원색**이라 그대로 쓰지 말 것 — 주색을 정할 때 참고만 한다.

### 아군 6

| 이름 | id | 원소 (포인트로 넣을 색) | 물리 | 전투 클래스 | 역할 | 무기 실루엣 힌트 |
|---|---|---|---|---|---|---|
| 하랑 | `harang` | 충격 `#E8E8E8` | 참격 | 파괴자 | 탱커 | 양손 대검 — 어깨에 걸침 |
| 미나 | `mina` | 화염 `#FF6B35` | 강타 | 수호자 | 탱커 | 대형 방패 + 단봉 |
| 설아 | `seola` | 한기 `#4FC3F7` | 관통 | 조율자 | 버퍼 | 세장한 지휘봉·창 |
| 태희 | `taehee` | 침식 `#7C4DFF` | 참격 | 잠식자 | 원거리딜러 | 곡도 2정 또는 사슬 |
| 아린 | `arin` | 전격 `#B388FF` | 관통 | 추격자 | 원거리딜러 | 활 또는 석궁 |
| 강지 | `gangji` | 광휘 `#FFD54F` | 강타 | 치유자 | 버퍼 | 지팡이·향로 |

> 무기 힌트는 **클래스·물리 타입에서 끌어낸 제안**이다. 저작된 무기 디자인이 있으면
> 그쪽이 정본이다. 물리 타입은 전투 규칙(자물쇠 해제 조건)이므로 무기 모양이 그것과
> 어긋나면 플레이어가 헷갈린다 — 참격은 날붙이, 관통은 찌르기/사격, 강타는 둔기.

### 적 6

적은 전원 원소가 **충격**이라 원소색 포인트가 겹친다. 대신 **약점 속성**을 몸 어딘가에
드러내면 전장에서 분절 바와 짝지어 읽힌다(선택).

| 이름 | id | 약점 | 초상 아트 | 비고 |
|---|---|---|---|---|
| 매머드 수인 | `mammoth_beastfolk` | 화염 · 광휘 | 없음 | 거구, 상아 |
| 매머드 우두머리 | `mammoth_boss` | 한기 · 화염 | 없음 | 위 개체의 대형·장식 강화판 |
| 벨로시랩터 수인 | `velociraptor_beastfolk` | 한기 · 충격 | 있음 (`girl_violet`) | 민첩, 낮은 자세 |
| 벨로시랩터 수인 2 | `velociraptor_beastfolk_2` | 전격 | 있음 | 위와 같은 종, 색 계열만 다르다 |
| 서아 | `seoa` | 침식 · 한기 · 충격 | 있음 (`seoa`) | **뿔과 꼬리가 달린 소녀.** 지금 전장에서 돌창병으로 보인다 |
| 여왕 | `pterosaur_queen` | 전격 · 광휘 | 없음 | 익룡, 날개. 보스 |

> **초상이 있는 셋은 초상을 먼저 보여 주고 그리게 한다.** 같은 인물이 전장과 초상에서
> 다르게 생기면 그게 제일 먼저 눈에 걸린다. 서아가 지금 정확히 그 상태다.

# §A — Codex 레인: 네모 대체 플레이스홀더 생성기

**목표: 오늘 네모를 없앤다.** 얼굴은 없어도 되지만 실루엣·무기·팔레트로 12체가
서로 구분되어야 한다.

작성해 줘. 얼굴 없는 단순 실루엣이면 되고, 12체가 서로 확실히 구분되는 것이 목표다.

## A-1. 뽑은 뒤 배선

```
assets/sprites/characters/battle/char_<id>_battle.png
assets/sprites/enemies/battle/enemy_<id>_battle.png
```

에 넣고, 각 `.tres` 의 `battle_sprite` 에 지정한다. `.import` 파일도 함께 커밋한다
(없으면 `ResourceLoader.exists()` 가 false 를 돌려줘 코드가 파일을 못 찾는다).

브랜치를 옮긴 뒤에는 먼저 `godot --headless --path . --import` 를 돌린다.

# §B — 이미지 생성 레인: 최종 전투 스프라이트

아래 템플릿의 `【 】` 만 §3 표에서 채워 넣는다. 템플릿은 자기 완결적이다.

```
2D 게임에 바로 넣을 **측면 전투 자세 캐릭터 스프라이트** 한 장을 만들어 줘.
배경은 완전 투명, 인물 한 명만.

■ 캔버스와 구도
- 캔버스 【224 x 336 (아군) / 248 x 312 (적)】 px, 배경 완전 투명
- **4등신 치비.** 머리가 전체 높이의 1/4. 게임에서 84px 로 축소되므로 7등신으로
  그리면 얼굴이 사라진다
- **발끝을 캔버스 밑변에 붙인다.** 게임이 발밑을 기준점으로 잡는다
- 좌우 각 5%, 위 5% 는 비워 둔다
- 【오른쪽 / 왼쪽】을 보는 측면 3/4 시점
- **제자리 전투 대기 자세.** 무기를 들고 무게중심을 약간 낮춘다.
  걷는 중간 자세·달리는 자세 금지

■ 캐릭터
- 이름 【 】
- 무기 【 】
- 특징 【 】
- 【초상 이미지를 첨부한 경우: 첨부한 초상과 같은 인물이다. 머리 색·머리 모양·
  의상 실루엣·장식을 그대로 따르고, 그것을 4등신 전투 자세로 옮겨 그려라】

■ 색 규율 (어기면 게임 화면에서 무너진다)
- 팔레트 **4색 이내**: 주색 2 + 음영 1 + 강조 1
- **원소 색 【#______ 】를 의상이나 무기의 한 곳에** 포인트로 반드시 넣는다.
  전투 중에 이 색이 곧 속성 표시다. 두 곳 이상에 쓰지 마라
- 그림자에 **순수 검정을 쓰지 마라.** 주색의 보색 계열 어두운 톤을 쓴다
- 게임 배경이 #0C111C, 바닥이 #141C2C 인 어두운 화면이다. 그보다 밝아야 묻히지 않는다
- 과채도 금지

■ 조명
- **좌상단 45° 고정.** 다른 캐릭터와 같은 방향이어야 한 세트로 보인다
- 원소 색 조명·발광·스피드라인을 **그림에 굽지 마라.** 게임이 코드로 합성한다
- 캐릭터 외곽에 1~2px 밝은 림 라이트. 어두운 배경에서 인물을 떼어 낸다

■ 하지 말 것
- 접지 그림자 (게임이 그린다)
- 배경, 바닥, 이펙트, 텍스트, 프레임, 여러 컷
- 팔다리를 캔버스 밖으로 내보내기 (잘린다)
```

## B-1. 유닛별 채워 넣는 값

§3 의 표를 그대로 옮긴다. 예를 들어 미나는 이렇게 된다.

```
- 캔버스 224 x 336
- 오른쪽을 보는 측면 3/4
- 이름 미나
- 무기 대형 방패 + 단봉
- 특징 수호자. 방패를 앞으로 내밀고 자세를 낮춘 방어 태세
- 원소 색 #FF6B35 (화염)
```

여왕은 이렇게 된다.

```
- 캔버스 248 x 312
- 왼쪽을 보는 측면 3/4
- 이름 익룡 여왕
- 무기 없음 (부리와 갈고리 발톱)
- 특징 보스. 부채꼴 날개 2장을 펼친 익룡. 다른 적보다 1.3배 크게 보이도록 화면을 꽉 채운다
- 원소 색 #B388FF (전격 — 약점이 전격이라 그 색을 장식에 넣는다)
```

## B-2. 순서 — 작은 것부터

가이드 §0 의 순서를 이 에셋에도 적용한다.

1. **한 명만 먼저 뽑아 84px 로 줄여 본다.** 줄여서 누구인지 모르면 나머지 11체를
   뽑는 것은 낭비다
2. 그 한 명을 **검은 실루엣으로 칠해** 본다. 실루엣으로 구분되지 않으면 색을 바꿔도
   전장에서 구분되지 않는다
3. 통과하면 같은 대화에서 나머지를 이어 뽑는다 — 대화를 새로 열면 화풍이 어긋난다
4. 6명을 **나란히 84px 로 놓은 시트**를 만들어 확인한다

## B-3. 확인 항목

- [ ] 84px 로 줄였을 때 6명이 서로 구분되는가
- [ ] 검은 실루엣만으로 구분되는가
- [ ] 배경이 완전 투명인가 (알파 0, 흰 배경이 아님)
- [ ] 발끝이 캔버스 밑변에 붙어 있는가
- [ ] 광원이 좌상단 45° 로 전원 같은가
- [ ] 팔레트가 4색 이내인가
- [ ] 자기 원소 색이 **한 곳에** 포인트로 들어갔는가
- [ ] 원소 조명·발광이 그림에 구워지지 않았는가
- [ ] 접지 그림자가 그림에 없는가
- [ ] 어두운 배경(#0C111C)에 얹었을 때 묻히지 않는가
- [ ] 초상이 있는 유닛(서아·벨로 2종)은 초상과 같은 인물로 보이는가
