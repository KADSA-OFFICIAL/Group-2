# 전투 프레임 시트 프롬프트 (#487)

전투 유닛을 정지 한 장에서 **움직이는 그림**으로 바꾸기 위한 규격과 프롬프트.

각 프롬프트는 **자기 완결적**이다 — 생성 도구는 이 저장소를 읽지 못한다.
값이 바뀌면 프롬프트가 아니라 아래 정본을 본다.

| 대상 | 정본 |
|---|---|
| 애니메이션 이름·프레임 수·fps·루프 | `entities/combat/turn/BattleAnimation.gd` |
| 표시 칸·발 기준선 | `stage/turn/TurnBattle.gd` 의 `ALLY_BODY` / `ENEMY_BODY` |
| 화풍·색감·캐릭터 정체성 | `assets/sprites/characters/portraits/*.png` |
| 정지 스프라이트 규격 | [turn-battle-sprite-prompts.md](turn-battle-sprite-prompts.md) |

---

## 0. 왜 4종뿐인가

**재생 경로가 있는 것만 그린다.**

| 전투 화면의 연출 이벤트 | 애니메이션 | 재생 |
|---|---|---|
| (대기) | `idle` | 루프 |
| `SKILL_CAST` → `_play_cast()` | `attack` | 1회 후 idle |
| `HIT` → `_play_hit()` | `hit` | 1회 후 idle |
| `DEATH` → `_play_death()` | `death` | 1회 후 **마지막 프레임 유지** |

`pixel-art-prompts.md` 가 적어 둔 교훈 그대로다: *"재생 코드가 없는 애니메이션은
요구하지 않았다. 프롬프트에 넣으면 창고에 쌓인다."* 승리 포즈·이동·버프 반응은
이 화면에 재생 경로가 없으므로 **그리지 않는다.**

`idle` 만 그려도 동작한다. 나머지는 없으면 그 동작에서 기존 트윈(전진·넉백·명멸)만
남는다 — 화면이 깨지지 않는다. **한 캐릭터씩 idle → attack → hit → death 순으로
채워 나가도 된다.**

---

## 1. 시트 규격

### 1-1. 한 장짜리 시트를 받지 않는다 — 낱장으로 받는다

```
assets/sprites/characters/battle/frames/<id>/<anim>_<n>.png    아군
assets/sprites/enemies/battle/frames/<id>/<anim>_<n>.png       적

예: harang/idle_0.png  harang/idle_1.png  ...  harang/attack_0.png
```

생성 도구는 스프라이트 시트의 격자를 정확히 못 맞춘다. 이 프로젝트가 이미 겪었다 —
`tools/normalize_walk_sheet.gd` 머리말: *"셀 폭이 정수로 나뉘지 않는다"*,
*"프레임마다 캐릭터가 셀 안에서 한쪽으로 흘러간다(약 29px/프레임). 그대로 재생하면
제자리걸음이 아니라 옆으로 미끄러진다."*

**낱장은 이 문제가 아예 없다.** 한 컷이 마음에 안 들면 그것만 다시 뽑으면 된다.
조립은 도구가 한다.

```bash
godot --headless --path . --script tools/build_battle_frames.gd
```

→ `frames/<id>.tres` (`SpriteFrames`) 가 나온다. 그걸 `.tres` 의 `battle_frames` 에 넣는다.

### 1-2. 캔버스 — 정지 스프라이트와 **똑같이**

| 대상 | 캔버스 | 화면 표시 |
|---|---|---|
| 아군 | **224 × 336** | 56 × 84 |
| 적 | **248 × 312** | 62 × 78 |

**모든 프레임이 같은 크기여야 한다.** 프레임마다 크기가 다르면 인물이 프레임 사이에서
튄다. 조립 도구가 경고하고 검증이 실패한다.

**발끝은 모든 프레임에서 캔버스 밑변에 붙인다.** 셀 밑변이 발 기준선이고, 화면이
그 자리를 노드 원점으로 잡는다. 한 프레임만 발이 떠 있으면 그 순간 캐릭터가 점프한다.

### 1-3. 프레임 수와 속도

| 동작 | 프레임 | fps | 루프 | 길이 |
|---|---|---|---|---|
| `idle` | 4 | 6 | **예** | 0.67초 |
| `attack` | 4 | 14 | 아니오 | 0.29초 |
| `hit` | 2 | 16 | 아니오 | 0.13초 |
| `death` | 4 | 8 | 아니오 | 0.50초 |

컷이 적은 이유 두 가지. (1) 화면 표시 높이가 84px 이라 프레임을 늘려도 차이가 보이지
않는다. (2) **같은 캐릭터를 여러 컷으로 일관되게 뽑는 것이 이 프로젝트에서 이미
실패한 적이 있다.** 컷이 적을수록 흔들림이 적다.

`hit` 이 2컷·16fps 로 가장 짧은 이유: 타격 규격표의 히트스톱이 2~12프레임이라,
피격 모션이 그보다 길면 히트스톱이 끝난 뒤에도 움츠린 자세가 남아 다음 타격과 겹친다.

> 배속(1×/2×/3×)은 화면이 `speed_scale` 로 따로 곱한다. **프레임을 더 그릴 필요 없다.**

## 2. 생성 절차 — 기준 컷부터

이 순서를 지키지 않으면 4컷이 서로 다른 캐릭터처럼 나온다.

1. **기준 컷 한 장.** 이미 있는 `battle_sprite`(`assets/sprites/characters/battle/char_<id>_battle.png`)
   가 곧 `idle_0` 이다. **새로 그리지 말고 그것을 복사해 `idle_0.png` 로 쓴다.**
   화풍·색감·의상이 이미 검수를 통과한 그림이다.
2. **같은 대화에서** 나머지 컷을 이어 뽑는다. 대화를 새로 열면 화풍이 어긋난다.
3. 한 동작을 다 뽑을 때마다 **4컷을 나란히 놓고** 본다. 의상 장식·머리 길이·무기 크기가
   컷마다 달라지지 않았는지.
4. 84px 로 줄여서 본다. 그 크기에서 안 보이는 차이는 그리지 않아도 된다.

## 3. 프롬프트 — 동작별

`【 】` 만 채운다. **기준 컷(`idle_0`)을 반드시 첨부한다.**

### 3-1. idle (4컷, 루프)

```
첨부한 그림과 **완전히 같은 캐릭터**의 대기 애니메이션 4컷을 만들어 줘.
첨부 이미지가 1번 컷이다. 2·3·4번 컷을 그려 줘.

■ 규격 — 4컷 모두 동일
- 캔버스 【224 x 336 (아군) / 248 x 312 (적)】 px, 배경 완전 투명 PNG
- **발끝을 캔버스 밑변에 붙인다.** 모든 컷에서 발 위치가 같아야 한다
- 인물의 크기·위치·비율이 컷마다 변하면 안 된다. 캔버스 안에서 인물이 이동하지 않는다
- 첨부한 그림의 머리 모양·의상·장식·무기·색을 **하나도 바꾸지 마라**

■ 동작 — 제자리 호흡. 루프한다
- 1번(첨부) 기본 자세
- 2번 숨을 들이쉬어 가슴과 어깨가 **2~3px 올라간다.** 머리카락 끝과 옷자락이 살짝 뒤로
- 3번 최고점. 어깨가 4px 올라가고 무게중심이 아주 살짝 뒤
- 4번 내쉬며 1번으로 돌아가는 중간. 어깨 2px
- **4번 다음에 1번이 이어진다.** 루프가 튀지 않게 4번을 1번에 가깝게 그린다
- 발은 움직이지 않는다. 걷거나 자세를 바꾸지 마라

■ 하지 말 것
- 표정 바꾸기, 무기 휘두르기, 몸 돌리기
- 배경, 바닥, 접지 그림자, 이펙트, 텍스트
- 캔버스 안에서 인물 크기나 위치 바꾸기
```

### 3-2. attack (4컷, 1회)

```
첨부한 그림과 **완전히 같은 캐릭터**의 공격 애니메이션 4컷을 만들어 줘.
첨부 이미지는 대기 자세이고, 여기서 시작해 무기를 휘두르는 4컷이다.

■ 규격 — 4컷 모두 동일
- 캔버스 【224 x 336 / 248 x 312】 px, 배경 완전 투명 PNG
- **발끝을 캔버스 밑변에 붙인다.** 모든 컷에서 발 위치가 같아야 한다
  (앞으로 나아가는 연출은 게임이 위치를 옮겨서 따로 한다 — 그림 안에서 이동하지 마라)
- 첨부한 그림의 머리 모양·의상·장식·무기·색을 하나도 바꾸지 마라

■ 동작 — 【무기: 예) 양손 대검을 어깨에서 내려친다】
- 1번 **준비.** 무기를 뒤로 당기고 몸을 살짝 비튼다. 무게중심 뒤
- 2번 **최대 준비.** 가장 크게 당긴 자세. 여기서 힘이 느껴져야 한다
- 3번 **타격 순간.** 무기가 가장 앞. 몸이 앞으로 기울고 무게중심 앞.
  이 컷이 가장 중요하다 — 게임이 여기서 화면을 흔들고 멈춘다
- 4번 **되돌아옴.** 휘두른 뒤 자세를 추스르는 중간. 대기 자세에 가깝게
- 4번 다음에 대기 자세로 돌아가므로, 4번을 첨부한 그림에 가깝게 그린다

■ 하지 말 것
- 이펙트·잔상·속도선 그리기 (게임이 코드로 합성한다)
- 캔버스 밖으로 무기 내보내기 (잘린다)
- 배경, 바닥, 접지 그림자, 텍스트
```

### 3-3. hit (2컷, 1회)

```
첨부한 그림과 **완전히 같은 캐릭터**의 피격 애니메이션 2컷을 만들어 줘.

■ 규격
- 캔버스 【224 x 336 / 248 x 312】 px, 배경 완전 투명 PNG
- **발끝을 캔버스 밑변에 붙인다**
- 첨부한 그림의 머리 모양·의상·장식·무기·색을 하나도 바꾸지 마라

■ 동작 — 짧고 강하게. 0.13초짜리다
- 1번 **충격 순간.** 상체가 뒤로 젖혀지고 어깨가 움츠러든다. 눈을 질끈 감거나 찡그린다.
  무기를 든 팔이 흐트러진다
- 2번 **버티는 자세.** 1번보다 살짝 회복. 아직 자세가 흐트러져 있다
- 두 컷 다 **대기 자세와 확실히 달라야 한다.** 0.13초 안에 읽혀야 하므로 과장한다
- 뒤로 밀리는 연출은 게임이 위치를 옮겨서 한다 — 그림 안에서 이동하지 마라

■ 하지 말 것
- 피·상처·이펙트 그리기 (게임이 명멸과 숫자로 표현한다)
- 배경, 바닥, 접지 그림자, 텍스트
```

### 3-4. death (4컷, 마지막 프레임 유지)

```
첨부한 그림과 **완전히 같은 캐릭터**의 사망 애니메이션 4컷을 만들어 줘.

■ 규격
- 캔버스 【224 x 336 / 248 x 312】 px, 배경 완전 투명 PNG
- 1~3번은 **발끝이 캔버스 밑변**에 있다. 4번은 쓰러진 자세라 몸이 바닥에 눕는다 —
  4번도 **인물의 가장 아래가 캔버스 밑변**에 닿아야 한다
- 첨부한 그림의 머리 모양·의상·장식·무기·색을 하나도 바꾸지 마라

■ 동작 — 무너진다. 마지막 컷에서 멈춘 채 남는다
- 1번 **힘이 빠진다.** 무기를 든 팔이 내려가고 고개가 숙여진다
- 2번 **무릎이 꺾인다.** 한쪽 무릎이 바닥으로. 무기를 놓치기 시작
- 3번 **무릎 꿇음.** 상체가 앞으로 무너진다
- 4번 **쓰러진 자세.** 이 컷이 화면에 **계속 남는다.** 보기 흉하지 않게,
  얼굴이 완전히 가려지지 않게 그린다
- 게임이 동시에 서서히 투명하게 만든다. 그림에 페이드를 그리지 마라

■ 하지 말 것
- 피·잔해·이펙트, 배경, 바닥, 접지 그림자, 텍스트
```

## 5. 뽑은 뒤

### 5-1. 조립

```bash
godot --headless --path . --script tools/build_battle_frames.gd
```

낱장이 하나도 없는 유닛은 건너뛴다. `<id>.tres` 가 나오면 그 캐릭터의 `.tres` 의
`battle_frames` 에 지정한다.

### 5-2. 검증

```bash
godot --headless --path . --import
godot --headless --path . tests/combat/VerifyBattleFrames.tscn --quit-after 400
godot --headless --path . tests/combat/VerifyTurnCombat.tscn --quit-after 400
```

`VerifyBattleFrames` 가 셀 크기·프레임 수·루프 설정·규약 밖 애니메이션을 본다.

### 5-3. 확인 항목

- [ ] 4컷이 **같은 캐릭터**로 보이는가 (의상 장식·머리 길이·무기 크기)
- [ ] 모든 프레임의 캔버스 크기가 같은가
- [ ] 모든 프레임에서 발끝이 밑변에 붙어 있는가 (`death` 4번은 몸의 가장 아래)
- [ ] `idle` 이 4번→1번으로 이어질 때 튀지 않는가
- [ ] `attack` 3번 컷이 타격 순간으로 읽히는가
- [ ] `hit` 두 컷이 대기 자세와 확실히 다른가
- [ ] `death` 마지막 컷이 계속 보여도 괜찮은 그림인가
- [ ] 84px 로 줄여도 동작이 읽히는가
- [ ] 배경이 완전 투명인가. 접지 그림자·이펙트가 그림에 없는가
- [ ] 게임에서 재생했을 때 인물이 옆으로 미끄러지지 않는가
